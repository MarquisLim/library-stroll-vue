# Заполнение базы и импорт настоящих артов

## Быстрый старт

В корне проекта, с PHP 8.2:

```powershell
php artisan data:setup
php artisan storage:link
php artisan artworks:import --source=met --limit=20 --publish
php artisan artworks:check-imports
```

`data:setup` применяет миграции и создаёт справочники ролей и причин жалоб. Он не очищает базу, не создаёт случайные работы и не скачивает изображения. `storage:link` нужен для отображения файлов через веб-сервер; существующие ссылки повторно создавать не требуется. Если терминал пока использует старый PHP, добавьте его папку в окружение текущего терминала:

```powershell
$env:Path = 'C:\OSPanel\modules\PHP-8.2;' + $env:Path
php -v
```

## Доступные команды

| Команда | Результат |
| --- | --- |
| `php artisan data:setup` | Миграции и обязательные справочники |
| `php artisan data:setup --demo-users` | Дополнительно тестовые пользователи, только local/testing |
| `php artisan artworks:import --source=met --limit=20 --publish` | До 20 новых опубликованных произведений Met |
| `php artisan artworks:import --source=met --query=landscape --limit=10 --publish` | До 10 новых произведений Met по запросу landscape |
| `php artisan artworks:import --query=cats --limit=5 --dry-run` | Показать названия, теги и источники без скачивания и записей |
| `php artisan artworks:import --query=flowers --limit=10` | Создать черновики; публикация включается только через `--publish` |
| `php artisan artworks:check-imports` | Проверить импортированные файлы, миниатюры, исходные теги и происхождение |
| `php artisan artworks:check-imports --source=met` | Проверить только один источник |
| `php artisan help artworks:import` | Полная справка по параметрам |

Новые тестовые аккаунты из `--demo-users` имеют пароль `password`; существующим аккаунтам сидер не меняет имя, пароль и роли. Их не следует использовать в production. Импорт музейных произведений не зависит от этих аккаунтов.

## Откуда берутся изображения и теги

Поддерживаются два официальных API без обязательного ключа:

- **Art Institute of Chicago** (`--source=artic`): название, художник, дата, техника, предметные теги, стиль, классификация и тип произведения. Источник: [документация API](https://api.artic.edu/docs/).
- **The Metropolitan Museum of Art** (`--source=met`, по умолчанию): название, художник, дата, техника, музейные subject tags, классификация и тип объекта. Используется актуальный paginated search `/public/collection/v1.1/search`, а затем запись конкретного объекта. Источник: [документация API](https://metmuseum.github.io/).

В импорт допускаются только записи, явно помеченные источником как Public Domain, с доступным изображением. Картинка и метаданные берутся из одной музейной записи. Случайная фотография не получает заранее выдуманное название или теги.

При проверке 24 октября 2026 года Met успешно отдал и метаданные, и изображение, которое прошло импорт и проверку. Art Institute отдавал метаданные, но его IIIF-сервер возвращал Cloudflare `403` из этого окружения. Для него следует сначала проверить `--dry-run`, а затем загрузку одного изображения; для рабочего наполнения в этом окружении используйте Met. Команда не обходит ограничения источника.

Оригинальные теги нормализуются: регистр, пробелы, дубли и префикс `#`. Для известного словаря добавляются русские соответствия, например `cats → кот`, `landscape → пейзаж`, `post-impressionism → постимпрессионизм`. Английские теги сохраняются. Словарь находится в `app/Services/ArtworkImport/SourceTags.php`; незнакомые термины остаются на языке источника, их перевод не выдумывается.

Поисковый запрос **не становится тегом**. Например, музей может найти работу по слову `cat` из исторического контекста, а изображение не содержать кота. В таком случае `кот` не добавляется, если соответствующего subject tag нет в метаданных. Эти теги — музейная каталогизация, а не результат проверки vision-моделью: возможны исторический контекст и неполнота разметки.

Из музейных текстов не копируется длинное кураторское описание. Описание работы формируется из фактических полей: художник, дата, материал, ссылка на источник и лицензия изображения. Исторический автор указывается в описании, а владельцем записи на платформе остаётся выбранный пользователь или отдельный аккаунт импорта.

## Владелец и коллекция

Без `--user` при первой успешной загрузке создаётся аккаунт `museum-imports@libstroll.test` с именем «Музейные произведения» и случайным паролем. Пароль не выводится; это технический владелец, а не новый пользователь с известным паролем.

Чтобы работы можно было редактировать в своей студии, передайте ID собственного пользователя:

```powershell
php artisan artworks:import --source=met --query=landscape --user=3 --limit=10 --publish
```

Чтобы добавить новые работы в существующую коллекцию этого же владельца:

```powershell
php artisan artworks:import --source=met --query=flowers --user=3 --collection=2 --limit=10 --publish
```

ID приведены как примеры. Коллекция должна существовать и принадлежать указанному `--user`; команда проверяет это до обращения к источнику. Повторный импорт уже существующего объекта не переносит его между владельцами и не добавляет его в другую коллекцию: существующая работа пропускается целиком.

## Лимиты, повторы и ошибки

`--limit` задаёт максимум **новых** работ, от 1 до 200. Каждая страница источника содержит до 40 кандидатов. По умолчанию просматриваются максимум три страницы; можно изменить начальную страницу и глубину:

```powershell
php artisan artworks:import --source=met --query=landscape --limit=50 --page=4 --max-pages=5 --publish
```

`--page` допускает 1..1000, `--max-pages` — 1..10. Глубокие страницы могут ограничиваться самим API. Если записей с подходящими изображениями недостаточно, команда сообщает, что лимит не достигнут. У Met без запроса используется `painting`, у Art Institute — доступные публичные произведения.

Для каждого объекта сохраняется уникальная пара `source + external_id` в таблице `artwork_imports`. Повторный запуск пропускает уже импортированные объекты, сохраняет ручные изменения и может импортировать следующие новые результаты в пределах выбранных страниц. Уникальность обеспечивается и на уровне БД. Одинаковое произведение, опубликованное в двух разных музеях с разными ID, считается двумя разными источниками; межмузейная дедупликация по изображению не реализована.

Изображение сначала скачивается во временную папку и проверяется по содержимому. Принимаются JPEG, PNG и WebP не более 15 MiB и 40 MP. Затем создаются работа, provenance-запись, теги и медиа с миниатюрой. При сбое загрузки работа не создаётся; при сбое транзакции записи откатываются, скопированное медиа удаляется. Временный файл удаляется после обработки.

Разрешены HTTPS-хосты изображений музейных API; автоматические редиректы отключены. Если музей меняет CDN или начинает перенаправлять URL, команда выдаст ошибку вместо загрузки произвольного адреса. Список хостов можно обновить в `ArtworkImageDownloader` после проверки нового домена.

На каждую запись печатается результат, в конце — количество созданных, пропущенных и ошибочных записей. Любая ошибка API/обработки даёт код завершения **1**, некорректные параметры — **2**. Успешно импортированные до ошибки работы сохраняются; повторный запуск пропустит их и продолжит обработку. Нехватка подходящих результатов без технических ошибок сопровождается предупреждением, но возвращает **0**.

После трёх ошибок импорта подряд обработка останавливается. Это предотвращает перебор десятков изображений при недоступном CDN или ошибке настройки медиа.

`--dry-run` читает API и проверяет дубли, но не скачивает изображения, не создаёт пользователя и не пишет в БД. Он не гарантирует, что CDN изображения будет доступен во время настоящего импорта. Для проверки дублей таблица `artwork_imports` должна уже существовать: сначала выполните `data:setup` или `migrate`.

## Что проверяет artworks:check-imports

Проверяются только работы с provenance в `artwork_imports`; старые и пользовательские работы не затрагиваются. Проверка подтверждает наличие одного читаемого оригинала, валидное изображение, совпадение SHA256 с импортированным файлом, наличие миниатюры на диске, сохранность всех исходных тегов и заполненные источник/лицензию. Дополнительные пользовательские теги допустимы.

Если исходные теги намеренно удалены или оригинал заменён, проверка это отмечает. Отсутствие импортов также возвращает код 1 с пояснением. Здесь нет произвольных требований «минимум 40 артов» или «минимум 13 пользователей».

## Что изменилось в старых сидерах

- `DatabaseSeeder` теперь создаёт только роли и причины жалоб. Повторный `db:seed` не запускает сетевые загрузки, массовую публикацию и генерацию лайков.
- `ArtworkSeeder` оставлен как совместимая обёртка вокруг нового музейного импорта. Предпочтительнее вызывать `artworks:import` напрямую: у него есть параметры и предварительный просмотр.
- Неиспользуемый `SeedImageResolver` удалён: он подбирал произвольную картинку отдельно от заранее заданных метаданных.
- `seed:check` перенаправляет на `artworks:check-imports` и проверяет новый импорт.
- `UserSeeder` вызывается явно, ограничен local/testing и сохраняет пароль/имя/роли уже существующих аккаунтов.
- `TagSeeder`, `VideoArtworkSeeder`, `CollectionSeeder` и `ArtworkEngagementSeeder` сохранены как отдельные необязательные demo-сценарии. Они не входят в стандартное заполнение и не применяются к музейному импорту автоматически. Старые тематические коллекции и наборы тегов не являются каталогом музейных произведений.
- Генератор аватаров сохранён для необязательных demo-пользователей; изображения артов новый импорт не генерирует.

**Существующие работы, медиа, коллекции и теги автоматически не удаляются.** У старых сидеров нет достоверного provenance, позволяющего безопасно отличить их данные от вручную созданных. Если требуется полностью пустая база, `migrate:fresh` уничтожит её содержимое; такая очистка не входит в команду импорта и при разработке этой функции не выполнялась.

## Связь с Ollama и семантическим поиском

Без `--index` импорт работает независимо от Ollama, FastAPI и Qdrant. Музейные теги записываются в обычную связь `artwork_tag`, `has_ai=false`.

Для векторов используйте `php artisan artworks:import --source=met --limit=20 --publish --index`. Он создаёт `pending` и отправляет задания в очередь `ai`; после успешной обработки worker заполняется Qdrant. Для старых работ используются `ai:index-artwork <id>` и `ai:reindex-all`. Обёртка `ArtworkSeeder` включает индексацию автоматически при `AI_SERVICE_ENABLED=true`. Настройка сервисов и проверка состояния описаны в [инструкции векторной индексации](ai-indexing-setup.md).

## Проверки реализации

Feature-тесты используют SQLite в памяти, HTTP fake и отдельный public disk. Проверяются привязка тегов к музейной записи, русские соответствия, повторы без перезаписи, dry-run, фильтр Public Domain, невалидный файл, владелец коллекции, API Met v1.1, проверка повреждённых данных, справочники и сохранение существующих паролей.

Реальные сетевые smoke-тесты выполняются отдельно на SQLite в памяти с медиа в `storage/framework/testing`; рабочую MySQL они не наполняют.

На 24 октября 2026 года финальный сетевой тест Met создал две работы (`552027` и `570722`), сохранил их файлы и миниатюры; `artworks:check-imports` завершился с кодом 0. В этом опыте использовались обычные настройки обработки изображений, включая оптимизаторы, и отдельная временная папка PHP внутри проекта. Эти две записи существовали только в тестовой SQLite в памяти.
