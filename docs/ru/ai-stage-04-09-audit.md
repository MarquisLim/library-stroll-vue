# 4.9-1 — Итоговый технический аудит AI-системы

## 1. Краткое резюме

Ветка `docker`, снимок кода `38bee02`. Штатный конвейер анализа и Dense-индексации пригоден как основа исследовательского ассистента. Hybrid Search работает с лексической выдачей и Dense, а опциональный ColBERT улучшил ранжирование на проверенной выборке. Отдельный контур подтвердил запись, удаление, перезапуск и ручное восстановление ColBERT. Исторический аудит 4.1 остаётся открытым. Для production требуется проверить согласованность записей при сбоях и конкуренции, полноту индексов, эксплуатационные границы доступа и допустимость лицензии модели. [Итог 4.7](ai-stage-04-07-final-summary.md) · [Дорожная карта](ai-roadmap.md).

Аудит сверяет код, отчёты и сохранённые артефакты. Последнее подтверждённое состояние каждого контура относится к указанному прогону. Действующие сервисы, базы и тома в 4.9-1 не проверялись повторно.

## 4. Архитектура и взаимодействие компонентов

**Фоновая запись.** Laravel → Redis → `worker-ai` → FastAPI → Ollama → Qdrant. После подтверждения текущей ревизии Laravel сохраняет результат в MySQL и при включённой синхронизации ставит отдельную задачу ColBERT. **Поисковое чтение.** Vue/Inertia → Laravel Hybrid Search → FastAPI/Ollama/Qdrant → опциональный ColBERT → RRF и фильтрация в Laravel → карточки работ. [Задача индексации](../../app/Jobs/AnalyzeAndIndexArtworkJob.php) · [Сервис поиска](../../app/Services/Search/HybridSearchService.php).

1. **Vision-анализ.** AI Job отправляет миниатюру при её наличии, иначе оригинал для изображения. FastAPI передаёт изображение и текстовый контекст в Ollama `/api/chat` и валидирует ответ по схеме метаданных. Без изображения выполняется анализ текста. При отказе Vision и наличии текстового контекста возможен `text_fallback`, который фиксируется отдельно. Значение Vision по умолчанию — `qwen3-vl:4b`. В поздних исследовательских прогонах явно использован `qwen3-vl:4b-instruct`. [Клиент Ollama](../../ai-service/app/clients/ollama.py) · [Сервис анализа](../../ai-service/app/services/artwork_service.py) · [Корпус и модели](ai-stage-04-04-dataset.md).
2. **Поисковое представление.** Laravel составляет `searchable_text` из названия, описания, summary, двуязычных AI-тегов, авторских тегов, объектов, тем, стилей, настроения и цветов. AI-метаданные и результат попытки сохраняются в MySQL. Хеш ревизии работы и SHA-256 поискового текста используются для разных проверок. [Сборка текста и запись](../../app/Jobs/AnalyzeAndIndexArtworkJob.php) · [Ожидание ColBERT](../../app/Models/ArtworkColbertExpectation.php).
3. **Dense.** FastAPI вычисляет embedding текста через Ollama `/api/embed` и сохраняет в Qdrant вектор и payload с ID, хешем ревизии и версиями схемы и prompt. `/api/v1/search` кодирует текст запроса. `/api/v1/similar` использует вектор исходной работы. Оба маршрута проверяют доступ через Laravel и при недоступности проверки возвращают 503. Для similar доступность исходной работы проверяется до и после запроса к Qdrant. [Маршруты](../../ai-service/app/api/routes.py) · [Клиент Qdrant](../../ai-service/app/clients/qdrant.py) · [Внутренний контроллер видимости](../../app/Http/Controllers/Internal/ArtworkVisibilityController.php).
4. **Лексика и RRF.** Laravel выбирает публичные работы по `title LIKE` и упорядочивает их по лайкам. RRF суммирует вклады обратных рангов двух веток. Laravel затем повторно применяет видимость и фильтры, загружает модели и формирует страницу. Семантический сбой оставляет лексическую выдачу. [Hybrid Search](../../app/Services/Search/HybridSearchService.php) · [RRF](../../app/Services/Search/ReciprocalRankFusion.php) · [Laravel/Inertia](../../app/Http/Controllers/SearchController.php).
5. **ColBERT.** Модель кодирует запрос и поисковые **тексты** на уровне токенов и вычисляет MaxSim. Пиксели анализируются в Vision-ветке. Laravel обращается к отдельному сервису по `AI_COLBERT_URL` и принимает только перестановку переданных ID с валидными рангами. Кандидаты после топ-30 сохраняют порядок. Сбой, неполный ответ или неизвестный документ приводят к Dense-порядку. Маршрут reranking основного FastAPI возвращает `reranked=false`. [HTTP-прототип](../../scripts/research/colbert_http.py) · [Ранжирование](../../scripts/research/colbert_rerank.py) · [Клиент Laravel](../../app/Services/AiService/HttpAiServiceClient.php) · [Маршруты FastAPI](../../ai-service/app/api/routes.py).
6. **Синхронизация, удаление и видимость.** После успешного Dense Laravel при включённой автоматизации сохраняет ожидание и зашифрованный текст. Задача сверяет текущее состояние работы и передаёт в ColBERT хеш и ожидаемую удалённую версию. Приватность, блокировка и удаление через штатные события сохраняют намерение очистки, выполняют Dense DELETE и затем ставят удаление ColBERT. Состояние версии и маркеры удаления сохраняются на диске. Право показа определяется текущими данными Laravel. [Обработчики видимости](../../app/Services/AiService/ArtworkIndexVisibility.php) · [Удаление Dense](../../app/Jobs/DeleteArtworkIndexJob.php) · [Клиент документов](../../app/Services/AiService/ColbertDocumentClient.php) · [Хранилище версий](../../scripts/research/colbert_state.py).
7. **Диагностика и восстановление.** `ai:health`, защищённая диагностика FastAPI и AI Monitor дают сведения о доступности и попытках. `ai:reconcile-artwork --dry-run` сверяет Dense по одному ID. `ai:reconcile-colbert --dry-run` сравнивает Laravel, Qdrant и ColBERT. `--apply` с подтверждением одного ID ставит repair в очередь при наличии подтверждённых данных. Обновление использует сохранённый текст, удаление требует подтверждённого отсутствия точки и успешного Dense-намерения. [Dense-инспекция](ai-stage-04-01-reconciliation-audit.md#9-диагностическая-команда-412b-2) · [Сервис восстановления ColBERT](../../app/Services/AiService/ArtworkColbertRepairService.php) · [AI Monitor](../../app/Http/Controllers/Admin/AiMonitorController.php).

## 6. Научные метрики

В 4.5A на 24 запросах с одной заранее выбранной целью Dense + ColBERT изменил Hit@1 с 13/24 до 19/24, Hit@5 с 16/24 до 23/24 и MRR@5 с 0,5972 до 0,8625. Все цели уже входили в исходный топ-30. В 4.5B-2 тот же результат подтверждён в реальном Laravel Hybrid Search. Для этих 24 запросов лексических совпадений не было. [4.5A и 4.5B-2](ai-stage-04-05-colbert-experiment.md).

**Человеческая оценка 4.8A-4 и статистическая проверка 4.8B-1.** A — Dense, B — Dense + ColBERT. В этих 40 запросах штатный LIKE дал пустую выдачу, поэтому Hybrid совпал с A, а Hybrid + ColBERT — с B.

Замеры характеризуют локальный исследовательский запуск. Параллельная production-нагрузка не измерялась. [Замеры 4.5](ai-stage-04-05-colbert-experiment.md) · [Замеры 4.8A-2](ai-stage-04-08-evaluation.md#задержка-и-воспроизводимость).

Границы вывода — 100 изображений, 40 запросов (20 RU и 20 EN), один разметчик, 595 определённых и 12 неопределённых оценок из 607 пар. Численные метрики используют неполный пул. Bootstrap описывает вариацию по запросам, а согласие между разметчиками и перенос на внешний корпус не оценивались. [Границы статистического вывода](ai-stage-04-08-evaluation.md#границы-вывода-и-воспроизведение).

## 9. Готовность к следующим этапам

**Готовность к прототипу 5.x подтверждена для изолированного исследовательского сценария.** Dense и Hybrid Search можно использовать как слой получения кандидатов. Вариант Dense + ColBERT доступен для сравнения при допустимой лицензии и включённых исследовательских флагах. Производственное использование требует отдельной проверки рисков из реестра, покрытия целевых данных, задержек под нагрузкой и правил доступа к контексту.

| Что переиспользовать | Что предстоит добавить для ассистента |
| --- | --- |
| Семантический API `/search`, `/similar`, Dense и Hybrid Search | Диалоговый поиск. Оркестрация запроса и уточнений, выдача кандидатов с текущими ограничениями пользователя. Оставить возможность работы без ColBERT. |
| Метаданные AI-анализа, канонические Laravel-модели и Media Library | RAG. Выбор источников после проверки доступа, бюджет контекста, границы доверия к полученному тексту и режим ответа при отсутствии подтверждения. |
| Текущие фильтры, учётные записи, Laravel/Vue и компоненты карточек | Контекст разговора и UI ассистента. Авторизация сессий, политика хранения истории и отдельная повторная проверка доступа при подстановке источников в следующий ответ. |
| ID работ, маршруты, изображения и превью, уже доступные приложению | Ответы со ссылками. Структурированный список проверенных ID и цитат с привязкой к исходным карточкам. Ссылки формирует приложение из доступных записей. |
| Vision-описания, двуязычные теги, метаданные Media Library и существующие превью | Структурирование медиаконтента. Выбрать схему фрагментов, кадров или транскриптов и способ хранить происхождение, версии и связь с исходной работой. |
| `ai_processing_runs`, статусы и диагностические команды | Отдельная наблюдаемость запросов ассистента. Журнал обработки работ полезен для эксплуатации индексов. Для диалогов нужны собственные события retrieval и генерации, границы доступа и срок хранения. |

В 4.9-2 предстоит согласовать последовательность работ 5.x и критерии допуска. Для первого прототипа достаточно подтверждённого retrieval по доступным изображениям и ответов с проверяемыми ссылками. Для выпуска потребуется отдельно определить критерии качества ответов, отказов при недоступности AI и согласованности данных под нагрузкой.
