# Демонстрационный каталог Library Stroll

Дата обновления: **11 ноября 2026 года**. Этап 1: оптимизация импорта и качества контента.

Команды `demo:populate`, `demo:verify`, `demo:sources-check` работают только в Laravel environment `local` и `testing`. Обхода production-ограничения нет. Импорт создаёт настоящие публикации с локальными медиа, кураторами, тегами и коллекциями. Демо-куратор владеет публикацией; оригинальный автор хранится отдельно в `artwork_imports.creator_name`. Неизвестный автор отображается как «Автор неизвестен».

Демо-работы имеют `is_demo=true`, `ai_indexing_enabled=false`, `has_ai=false`. Импорт не запускает LLM, Ollama, embeddings, Qdrant или задания AI. Запрет индексации действует также при включённом `AI_SERVICE_ENABLED` и запуске `ai:reconcile`. Архитектура AI на этом этапе не менялась.

## Где выполнять команды

Откройте **PowerShell в корне проекта**, например `B:\projects\library-stroll-vue`. Docker Desktop должен быть запущен; вставлять команды в интерфейс Docker Desktop не нужно.

Если ещё работает предыдущий импорт, дождитесь завершения или остановите через Ctrl+C. Не обновляйте контейнер посреди импорта. Затем:

```powershell
.\scripts\docker.ps1 up
.\scripts\docker.ps1 artisan migrate
.\scripts\docker.ps1 artisan demo:sources-check --media
```

`up` пересобирает образы и применяет код/настройки контейнеров. **Новых миграций на этом этапе нет**; `migrate` нужен, если не применена исходная `2026_11_10_100000_add_demo_content_fields.php`. Медиа и БД сохраняются в volumes. Не удаляйте volumes или manifest для обновления кода.

Для Docker настройки задаются в `docker/.env`, образец — `docker/.env.example`. Корневой `.env` относится к PHP на хосте. Переменные только в корневом `.env` не включают источник в Docker. Для разделения этапов можно оставить `AI_SERVICE_ENABLED=false`; защита демо-работ не зависит от этого значения.

Без Docker нужны PHP 8.5 с GD/fileinfo/curl, Node.js 22+ для аватаров, FFmpeg/FFprobe для видео, зависимости Composer/npm, миграции и ссылка `public/storage`. Используйте `php artisan ...` с теми же параметрами. После изменения `.env` сбросьте кэш конфигурации (`php artisan config:clear` или через Docker-обёртку).

## Продолжение существующего каталога

Старый **`balanced-42.json` остаётся на месте**. Продолжайте с тем же preset и seed:

```powershell
.\scripts\docker.ps1 artisan demo:populate --preset=balanced --images=50 --videos=0 --authors=8 --seed=42 --resume --recheck-skipped
.\scripts\docker.ps1 artisan demo:verify
```

`--images`/`--videos` — итоговые цели набора, а не число дополнительных строк. Переход с 50 на 600 не удаляет ранее сохранённые работы:

```powershell
.\scripts\docker.ps1 artisan demo:populate --preset=balanced --images=600 --videos=20 --authors=45 --seed=42 --resume --recheck-skipped
```

Массовый запуск не нужен для проверки установки. При увеличении цели существующие работы не редактируются и не скачиваются заново. Снижение цели также не удаляет публикации.

## Новый pilot на 50 изображений

`pilot` использует **отдельный manifest** `pilot-42.json`. Он не переносит записи из `balanced-42.json`. Внешний ID уникален для всей платформы: работа другого набора остаётся там и учитывается как `existing`, а не копируется. Профили одного seed могут использоваться повторно без перезаписи биографий и аватаров.

```powershell
.\scripts\docker.ps1 artisan demo:populate --preset=pilot --images=50 --videos=0 --authors=8 --dry-run
.\scripts\docker.ps1 artisan demo:populate --preset=pilot --images=50 --videos=0 --authors=8 --resume
.\scripts\docker.ps1 artisan demo:verify
```

## Параметры

| Параметр | Значение |
|---|---|
| `--preset=balanced` | `balanced` или `pilot`, отдельный manifest |
| `--images=600`, `--videos=20` | Итоговые цели: 0–5000 изображений, 0–100 видео |
| `--authors=45` | 1–100 профилей |
| `--seed=42` | Стабильное распределение владельцев, профилей и дат |
| `--source=met,commons,openverse` | Ограничение включённых источников |
| `--batch=25` | Размер страницы и интервал вывода прогресса, 1–100 |
| `--dry-run` | Квоты без сети, БД, аватаров и записи файлов |
| `--resume` | Сверка БД и продолжение временных/незавершённых ошибок |
| `--recheck-skipped` | Повторная оценка сохранённых отказов по теме, данным, разнообразию и URL |
| `--repair-media` | Восстановление файлов при продолжении по безопасным правилам |
| `--verify` | Независимая общая проверка вместо наполнения |

Загрузки последовательные. Файловая блокировка запрещает два одновременных импорта. Rate limits сохраняются.

## Подключения и конфигурация

Подключения/пороги/запросы находятся в `config/demo_content.php`; тематический словарь — в `config/demo_relevance.php`.

```text
sources.<source>
  enabled, base_url, search_endpoint, detail_endpoint
  media_url_template, allowed_media_hosts, api_key
  request_timeout, connect_timeout, rate_limit
  retry_attempts, retry_delay, max_pages, weight, supported_media_types
sources.openverse
  client_id, client_secret, token_endpoint
sources.smithsonian
  search_query_template
relevance
  threshold, weights
presets.<preset>.<category>
  label, quota, queries, sources, synonyms, exclude (необязательно)
```

Пороги: `small_quota_threshold=10`, `max_creator_share=.25`, `max_source_share=.65`, `metadata_cache_limit=256`, `checkpoint_every=25`. `rate_limit` — запросов/секунду, `retry_delay` — миллисекунды. Диагностика ограничена `diagnostic_max_pages=1`, `diagnostic_page_size=10`, `diagnostic_candidates=5` возвращённых адаптером кандидатов.

| Источник | Формат и ограничения |
|---|---|
| [Met](https://metmuseum.github.io/) | `/public/collection/v1.1/search`, карточка `/public/collection/v1/objects/{id}`. Только `isPublicDomain=true` и доступное изображение. Старый `artworks:import` совместим. |
| [Chicago](https://api.artic.edu/docs/) | `/artworks/search`, JSON `params` с boolean-фильтром Public Domain, IIIF. Ответ 403 не обходится. |
| [Commons](https://www.mediawiki.org/wiki/API:Imageinfo) | `generator=search`, `imageinfo`, `extmetadata`, категории файла, автор и лицензия. Запрос не становится тегом. |
| [NASA](https://images.nasa.gov/docs/images.nasa.gov_api_docs.pdf) | `/search`, `/asset/{id}`. Предпочитаются совместимые medium/small файлы. Отдельные [NASA Media Usage Guidelines](https://www.nasa.gov/nasa-brand-center/images-and-media/); сомнительные/сторонние кредиты отбрасываются, CC0 не присваивается. |
| [Openverse](https://api.openverse.org/v1/) | `/images/`, поля `license`, `license_url`, `creator`, `foreign_landing_url`, `attribution`, `tags`. Добавлен в предпочтительные источники всех тем; участвует при `enabled=true`. |
| [Smithsonian](https://edan.si.edu/openaccess/docs/) | `/search`: `api_key`, `q=<тема> AND online_media_type:Images`, `start`, `rows`; `/content/{id}`. Разбираются `descriptiveNonRepeating.online_media`, `freetext`, `indexedStructured`. Только явное `media.usage.access=CC0`; `idsId` используется для официального IDS IIIF. |

В `docker/.env` (или корневом `.env` для PHP на хосте):

```dotenv
OPENVERSE_ENABLED=false
OPENVERSE_CLIENT_ID=
OPENVERSE_CLIENT_SECRET=
SMITHSONIAN_ENABLED=false
SMITHSONIAN_API_KEY=
```

Openverse можно включить анонимно без обоих credential-полей. Если заполнены оба, используется POST `/auth_tokens/token/` с `grant_type=client_credentials`, затем Bearer token с учётом срока действия. Отказ токена приостанавливает источник. Ключ Smithsonian обязателен: без него источник пропускается, остальные работают. Секреты не добавляются в Git, manifest, отчёты или консоль.

Openverse не разрешает произвольные URL. Доверенные хосты по умолчанию: `live.staticflickr.com`, `images.unsplash.com`, `upload.wikimedia.org`, `images.metmuseum.org`, `www.artic.edu`. Домен из API **не добавляется автоматически**. Другие URL получают `unsafe_media`, даже при подходящей лицензии. Расширяйте список только после проверки владельца CDN, без wildcard. Каждый разрешённый хост проходит защиту DNS/IP, HTTPS и запрет перенаправлений.

## Принятие кандидатов

Для Public Domain/CC0 оригинальный автор может отсутствовать или быть Unknown/Anonymous: в БД сохраняется `null`. Для CC BY обязательны известный автор, исходная страница, точная Creative Commons BY-ссылка и атрибуция. CC BY-SA, NC, ND и неизвестные права не принимаются. Нужны название, достоверные теги, HTTPS-ссылки источника/лицензии и доступный подходящий файл.

`CandidateRelevanceEvaluator` нормализует регистр/пробелы, использует границы слов и явные английские/русские синонимы. Wolf/волк относится к животным, хотя запрос был `animals`; `cat` не совпадает с `cathedral`. Подтверждение должно находиться в метаданных объекта, сам факт попадания в выдачу ничего не доказывает. `exclude` может исключать явно неподходящие объекты.

Веса: название 2, предметные теги 3, категории 3, классификация/стиль/тип объекта 2, разрешённое описание 1. Порог — 2; поле учитывается один раз. Описание участвует только для CC0/Public Domain. Manifest сохраняет `evaluation.accepted`, целочисленный `score`, `matched_fields`, `matched_terms`, `category`, `rule_version`, `rules_hash`. **Score — сумма правил, не вероятность.** Это воспроизводимый алгоритм для будущего сравнения; LLM здесь нет.

Поисковый термин не записывается в теги. `SourceTags` сохраняет английские термины и добавляет только известные русские соответствия. Длинные сторонние тексты не копируются в публикации: описание составляется из подтверждённых названия, автора, даты, техники, тегов и происхождения. HTML очищается и выводится как текст. Неизвестные сведения не выдумываются.

При квотах до 10 ограничения долей отключены. Для больших тем доля автора ограничена 25% (минимум две работы); неизвестные авторы не считаются одним автором. Доля источника 65% действует при наличии альтернатив. После отказа/исчерпания альтернатив оставшийся источник может заполнить квоту с сохранением требований к теме, лицензии и безопасности.

## Обнаруженные причины недобора

При проверке существующего `balanced-42.json` найдено **984 сохранённых кандидата**: 43 `imported`, 517 `diversity`, 163 `metadata`, 247 `license`, 14 `media_error`. Это фактический снимок manifest к моменту проверки, а не первоначальные 20 работ из сообщения. Главный численный барьер — ограничения разнообразия: Met дал 469 таких отказов. Старый код также отклонял материалы без автора, использовал подстроки запросов для темы и не пересматривал эти отказы при обычном resume. Отказы лицензии не считаются ошибкой фильтра и не снимаются ради количества. Chicago отдельно подтвердил HTTP 403 на медиа.

Openverse был настроен, но отсутствовал в списках категорий и имел пустой allowlist; Smithsonian искал также объекты без изображений и не использовал часть индексированных метаданных. Частые полные перезаписи manifest и лишнее продвижение генераторов добавляли накладные расходы. Все эти причины исправлены без замены адаптерной архитектуры.

## Скорость и безопасное продолжение

Перед поиском загружаются известные `(source, external_id)`. Met/Smithsonian пропускают такие ID до карточки; NASA не запрашивает assets для известных ID и запрещённых кредитов. Нет одинаковых поисковых запросов в одном запуске, действует ограниченный кэш ответов. До скачивания проверяются лицензия, метаданные, тема и разнообразие. После выполнения квоты генератор не продвигается к следующей карточке/странице.

Дедупликация — по внешнему ID и SHA-256 для старых/новых импортов. `image_sha256` совместим, `media_sha256` используется для универсального медиа. Perceptual hash пока не добавлен: разные перекодировки требуют ручной проверки. Похожие названия не объединяются.

Manifest: `storage/app/demo-import/manifests/<preset>-<seed>.json`. Сохранение атомарное через временный файл. Несущественные отказы сохраняются раз в `checkpoint_every`; до скачивания и сразу после завершённой публикации — обязательно. При Ctrl+C может потеряться только последняя группа отказов; завершённые публикации восстанавливаются по БД. Статус `processing` с уже созданной строкой признаётся завершённым после проверки файлов.

`--resume` сверяет manifest с БД, повторяет временные ошибки и обнаруживает отсутствующие/повреждённые файлы. Изменение тем, цели, источников или правил автоматически повторно оценивает применимые сохранённые отказы. `--recheck-skipped` делает это явно. Лицензионные отказы **не превращаются в допустимые автоматически**: новые данные о правах требуют отдельного рассмотрения.

```powershell
.\scripts\docker.ps1 artisan demo:populate --preset=balanced --images=50 --videos=0 --authors=8 --resume --recheck-skipped
.\scripts\docker.ps1 artisan demo:populate --preset=balanced --images=50 --videos=0 --authors=8 --resume --repair-media
```

Восстановление отсутствующего оригинала разрешено только при **точном совпадении сохранённого SHA-256**. Существующие изменённые байты не перезаписываются. Повреждённая/отсутствующая миниатюра пересоздаётся локально. Название, описание, пользовательские правки и связи не меняются. Отсутствующая запись Spatie или изменившийся оригинал требуют ручного рассмотрения. Удалённые пользователем публикации не создаются заново.

403/404 автоматически не повторяются. Для 429, временных серверных ошибок и таймаутов есть ограниченные retry/backoff с `Retry-After`; ожидание свыше 30 секунд приостанавливает попытку. Ошибка API выключает источник до следующего запуска, последовательные ошибки медиа тоже. Остальные источники работают. В консоли — HTTP-код без секретов. SSL не отключается, сеть автоматически не меняется.

## Диагностика и отчёты

```powershell
.\scripts\docker.ps1 artisan demo:sources-check
.\scripts\docker.ps1 artisan demo:sources-check --source=met,commons,openverse,smithsonian --media
.\scripts\docker.ps1 artisan demo:verify
```

Диагностика показывает отключённые источники и наличие ключа без раскрытия. Делает ограниченный read-only API-запрос; `--media` скачивает допустимый файл во временное хранилище, проверяет и удаляет. Каталог не меняется. Без проверки файла **Ready не выставляется**. `No eligible metadata` означает непригодную ограниченную выборку, а не поломку всего API.

Прогресс различает:

- API-кандидатов: строки/ID в реально полученных поисковых ответах текущего запуска, включая повторные ID в выдаче.
- Оценённых DTO: дошли до правил; это не количество скачиваний.
- Подходящих по теме: релевантны, но могут не пройти лицензию/метаданные.
- Попытки скачивания: HTTP после URL-политики, внутренние retry отдельно.
- Загруженные файлы: прошли проверку; ещё возможен SHA-дубликат.
- Новые публикации: сохранены именно в текущем запуске. Число изображений вверху — пригодный полный набор manifest.

Статусы: `imported`, `existing`, `duplicate`, `license`, `irrelevant`, `metadata`, `diversity`, `unsafe_media`, `media_error`, `repair_required`, `deleted`. Сохраняются причина, оценка и HTTP-код. `source_stats` содержит запросы/кандидатов/кэш/скачивания и `dataset_outcomes`; `category_stats` — цели/результаты и причины. `run_counters` относится к текущему запуску; `counts`/`dataset_outcomes` — к накопленному manifest. `api_errors` сохраняет историю. `shortfall`/`video_shortfall` — недобор.

`demo:verify` независимо проверяет профили/аватары, текст/теги, provenance/лицензии, оригиналы/хеши/миниатюры, видео/длительность/превью, коллекции и отсутствие AI. Проверяются **все демо-наборы**: недобор старого balanced может давать код 1 при готовом pilot. Консоль объясняет проблемы и недостающие темы. При неполном наборе: «Проверка завершена. Целевое количество изображений пока не достигнуто». Код 1 сохраняется; обёртка теперь объясняет, что это результат Artisan и отчёта, а не обязательно неисправность Docker.

Отчёты: `storage/app/demo-import/reports/`: `sources-*.json`, `<preset>-<seed>-*.json`, `verify-*.json`. В контейнере путь начинается с `/var/www/html/`, это не путь Windows. Медиа Spatie: `storage/app/public/<media-id>/`, аватары: `storage/app/public/profile-photos/`, временные загрузки: `storage/app/artwork-import-tmp/`.

## Профили, коллекции и безопасность медиа

Кураторы имеют `.test`-адреса, случайные непечатаемые пароли, биографии и локальные детерминированные PNG-аватары [DiceBear Lorelei (CC0)](https://www.dicebear.com/styles/lorelei/). Существующие профили не перезаписываются; число работ не выравнивается искусственно. Создаются тематические коллекции, максимум 24, на маленькой выборке меньше. Готовые коллекции автоматически не перезаполняются, чтобы сохранить пользовательские правки. Искусственных лайков/комментариев/рейтингов нет.

Изображения: JPEG/PNG/WebP до 15 MiB/40 MP; видео: MP4/WebM до 100 MiB/180 секунд с валидным потоком/длительностью по FFprobe. Проверяются реальные байты, точные доверенные HTTPS-хосты, публичные IPv4 с привязкой соединения к проверенному DNS. Редиректы, приватные/резервные IP, credentials и нестандартные порты запрещены.
