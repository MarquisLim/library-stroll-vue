# 4.5. ColBERT Reranking

## 4.5A. Dense Search и ColBERT Reranking

На 100 работах и тех же 24 запросах из 4.4C повторное ранжирование повысило Hit@1 с 13/24 до 19/24, Hit@5 с 16/24 до 23/24 и MRR@5 с 0,597 до 0,8625.

### Входные данные и метод

Из изолированного проекта `library-stroll-44-dataset` получены 24 ответа существующего поиска с лимитом 30, моделью `qwen3-embedding:0.6b` и прежним фильтром тестового автора. Порядок, ID и оценки Qdrant всех 720 кандидатов совпали с первыми 30 позициями выдачи 4.4C. Контрольные суммы 100 точек и SQL-снимков совпали до и после запросов.

Тексты собраны из сохранённых полей MySQL в порядке `AnalyzeAndIndexArtworkJob`. В текст входят название, описание публикации, AI-резюме, английские AI-теги, русские AI-теги, теги публикации, объекты, темы, стили, настроение и цвета. Использованы существующие значения. Изолированный поисковый стек остановлен после выгрузки. Дальнейший запуск проходил автономно, без сети и подключения к MySQL, Redis или Qdrant.

Исследовательский скрипт `scripts/research/colbert_rerank.py` использует `jinaai/jina-colbert-v2` с закреплённой ревизией весов `a9dc5cd7293d4c71dbbba04829923ba4d0e4f6ea` и ревизией реализации `bd55a5ec8e6c0fb1d6c26efb4b6a4a74ce8a88d3`. SHA-256 файла `model.safetensors` — `741387d37db6027ada13c4705b8bb32719a09dc71873f54814d1182cd8943806`. В обоих прогонах использованы Sentence Transformers `6.0.0`, Transformers `5.12.1`, PyTorch `2.8.0+cu126` и Tokenizers `0.22.2`. В карточке заявлены мультиязычная поддержка и лицензия CC BY-NC 4.0. [Карточка Jina ColBERT v2](https://huggingface.co/jinaai/jina-colbert-v2).

Токеновые представления строятся через `MultiVectorEncoder` с маркерами Jina и обученной проекцией в 128 измерений. Скрипт сверяет `linear.weight` проекции с исходным файлом весов. Для каждого токена запроса MaxSim находит максимальное скалярное сходство среди токенов документа, затем складывает максимумы. Сортировка идёт по убыванию MaxSim с сохранением порядка Dense при равенстве. Представления 99 уникальных кандидатов из всех списков подготовлены один раз. [Документация MultiVectorEncoder](https://sbert.net/docs/package_reference/multi_vector_encoder/model.html).

## 4.5B-1. Локальный HTTP-прототип

Отдельное FastAPI-приложение в `scripts/research/colbert_http.py` запускает `POST /api/v1/rerank` на локальном адресе. Оно переиспользует схемы `RerankRequest`, `RerankResponse` и `SearchResultItem` рабочего AI API. Вход содержит `query`, упорядоченный список `artwork_ids` из 1–30 уникальных целых ID и `limit`. ## 4.5B-2 — Laravel Hybrid Search

Laravel получает Dense-выдачу через `AI_SERVICE_URL` и передаёт первые 30 ID отдельному ColBERT-сервису. Принимается только полный переставленный список с последовательными рангами, конечными числовыми оценками и тем же набором ID. Позиции Dense с 31-й сохраняются, затем штатный RRF объединяет семантический и лексический списки. Laravel применяет фильтры, проверяет видимость и разбивает результат на страницы.

Если флаг выключен, Laravel пропускает HTTP-вызов ColBERT. При таймауте, ошибке HTTP или некорректном ответе исходный Dense-список поступает в тот же RRF. В журнале фиксируются количество кандидатов и время ColBERT либо класс ошибки, без запроса, ID и сообщения исключения.

### Запуск в тестовом контуре

Использованы сохранённые `library-stroll-44-dataset`, база `library_stroll_44_dataset` и коллекция `librarystroll_artworks_44_dataset`. Для прогона достаточно контейнеров MySQL, Qdrant, Laravel, Nginx и основного AI API. Команда запуска ColBERT из 4.5B-1 использует те же локальные веса и монтирования. Для этого контура параметры `--network bridge -p 127.0.0.1:50422:8001` заменены на `--network library-stroll-44-dataset_default --network-alias colbert`. Порт ColBERT доступен только в Docker-сети.

A/B-скрипт `storage/app/ai-stage-04-05/4.5b-2/hybrid-benchmark.php` вызывает реальный `HybridSearchService` в Laravel-контейнере. Для повтора в отдельный каталог внутри контейнера копируются скрипт, `query-plan.json` и `search-100.jsonl` из результатов 4.4C и `colbert-results.json` из 4.5A. Один процесс начинает с отключённым флагом, прогревает оба режима и чередует порядок A/B и B/A на 24 запросах. Настройки передаются этому процессу через `docker exec -e`. SQL-сессия открыта в режиме чтения.

Скрипт сравнивает фактический вход RRF с Dense и 4.5A, проверяет набор и видимость результатов для тестового автора, чужого автора и вторую страницу по пять работ. Для повтора проверки отказа рядом со скриптом нужен `search-ab.json` первого прогона. Повтор запускается с `DATASET_MODE=fallback` и `AI_RERANK_ENABLED=true` после остановки только ColBERT.

## 4.5B-3 — Быстрый fallback ColBERT

При остановленном контейнере имя `colbert` исчезает из Docker DNS. В изолированном Laravel на libcurl 7.88.1 один HTTP-вызов занимал 4,03 с при двухсекундном таймауте. Из них 4,00 с зарегистрировал сам cURL. Он вернул код 28, IP и время успешного TCP-соединения отсутствовали. Сокращение таймаутов до 200/500 мс без дополнительной настройки оставило задержку около 3,94 с. Сборка libcurl ожидала завершения потока разрешения имени перед возвратом ошибки. [Код DNS-резолвера libcurl 7.88.1](https://github.com/curl/curl/blob/curl-7_88_1/lib/asyn-thread.c#L487-L502).

Клиент ColBERT выполняет одну попытку HTTP. `AI_COLBERT_TIMEOUT` задаёт общее время в секундах, по умолчанию 0,5, с ограничением от 0,1 до 0,8. Установление соединения ограничено 200 мс или меньшим общим таймаутом. При наличии `CURLOPT_QUICK_EXIT` cURL возвращает управление по дедлайну, пока поток DNS завершает работу в фоне. Прямой замер с этой опцией дал 200–216 мс при том же отсутствующем имени. Сборки без опции применяют короткие HTTP-таймауты, а фактический предел ожидания DNS зависит от их резолвера. [Документация CURLOPT_QUICK_EXIT](https://curl.se/libcurl/c/CURLOPT_QUICK_EXIT.html).

`AI_RERANK_ENABLED=false` остаётся значением по умолчанию. Проверки JSON, оценок, рангов и состава кандидатов сохранены. Ошибка ColBERT передаёт исходный Dense-список в штатный RRF.
