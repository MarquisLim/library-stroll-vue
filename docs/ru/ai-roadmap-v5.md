# Дорожная карта AI Library Stroll 5.x

## 1. Цель следующего цикла

Ассистент помогает искать доступные изображения естественным языком, уточнять запросы и получать ответы с проверяемыми источниками. Сначала проверяется read-only поиск по существующему индексу. Затем добавляются модель для одного запроса, диалоговый контекст, RAG, интерфейс и подтверждаемые предложения по структурированию. Решение о выпуске принимается после испытаний и проверки условий допуска. [Подтверждённая архитектура 4.x](ai-stage-04-09-final.md).

## 2. Архитектурные принципы

1. **Laravel владеет поисковой операцией.** Авторизация, проверка доступа, получение кандидатов из `HybridSearchService`, повторное чтение MySQL, формирование ссылок и история ассистента находятся здесь. Прототип работает с опубликованными публичными изображениями. Исключаются заблокированные работы и авторы, записи с `ai_indexing_enabled=false` и работы вне права просмотра пользователя. Владелец и администратор тоже получают публичную выборку через ассистент. [Поиск Laravel](../../app/Services/Search/HybridSearchService.php) · [Политика просмотра](../../app/Policies/ArtworkPolicy.php).
2. **FastAPI выполняет ограниченную операцию LLM через Ollama.** Новая внутренняя операция принимает только оговорённые поля и использует схему результата. Права SQL, источники и ссылки разрешает Laravel. FastAPI получает минимум данных, достаточный для этой операции. Клиент Ollama для анализа метаданных остаётся отдельным от будущего адаптера ассистента. [Клиент Ollama](../../ai-service/app/clients/ollama.py) · [Текущие маршруты](../../ai-service/app/api/routes.py).
3. **Существующий Hybrid — основной режим.** Dense даёт кандидатов, Laravel объединяет их с LIKE через RRF и фильтрует выдачу. ColBERT остаётся опциональной перестановкой первых 30 Dense-кандидатов. Он выключен при первой приёмке. Ошибка этого сервиса оставляет Dense-порядок, ошибка генерации оставляет доступный результат поиска. Исключение или таймаут ассистента не запускает запись или повторную индексацию.
4. **LLM выбирает из серверного списка.** Laravel создаёт временные ссылки на отобранные источники и поля фактов. Модель может ссылаться только на элементы этого списка. Сервер формирует пользовательские URL из маршрута `artworks.show`. В 5.1 фактические фрагменты выводятся из проверенных полей, а AI-описания явно отмечаются как такие. Данные без достаточного основания остаются неизвестными. Заголовки, описания и теги отделяются от системных инструкций как недоверенные данные. Доступ к инструментам, сети, произвольным URL и базам из модели отсутствует. Структурированный результат проверяется по схеме и спискам серверных ссылок. Невалидный результат заменяется безопасной выдачей карточек или уточнением. [Маршрут публикации](../../routes/web.php).
5. **Доступ проверяется на каждом ходе.** Laravel перечитывает источники перед передачей в LLM и перед выдачей. При отзыве доступа во время генерации ответ, опирающийся на такой источник, отбрасывается, список перечитывается. История хранит ссылки на источники и версии отдельно от текста ответа. При чтении истории права перепроверяются, скрытые фактические фрагменты исключаются из UI и следующего контекста. Vue отображает текст безопасной интерполяцией и ссылки приложения.
6. **Бюджеты и журналы ограничены.** Первый поиск получает одну фразу до 500 символов, Laravel проверяет до 20 верхних результатов и возвращает до 20 карточек. Для 5.1 начальный бюджет — до 5 источников, до 4 предыдущих сообщений, до 2048 входных токенов вместе с инструкциями и до 256 токенов генерации. Адаптер должен уметь уложиться в бюджет выбранной модели и безопасно сокращать контекст или отказаться от генерации. Бюджет проверяется отдельно от числа карточек. Логи содержат идентификатор запроса, этап, время и безопасный код ошибки. Запросы, история, секреты и полный контекст в логи ассистента не попадают. [Существующие лимиты поиска](../../config/ai.php).

## 3. Этапы 5.0–5.6

### 5.0 — Базовый LLM-ассистент

**Цель и результат.** Один текстовый запрос возвращает доступные изображения с проверяемыми ссылками. Структурированный результат запроса подходит как для тестов API, так и для последующего UI. [Контракт 5.0-1](#7-план-первого-прототипа-50-1).

- [x] **5.0-1 · Контракт и retrieval.** Защищённый `POST /assistant/search` работает поверх Hybrid Search. Laravel повторно проверяет доступ и наличие изображения и формирует краткий JSON с канонической ссылкой. Прошли 50 целевых тестов на SQLite с HTTP-моками. Генеративная LLM отнесена к 5.0-2. [Реализация и проверка](ai-stage-05-00-assistant.md#50-1--защищённый-api-и-read-only-retrieval).
- [x] **5.0-2 · Один запрос LLM.** Laravel вызывает защищённую нормализацию FastAPI/Ollama под отдельным выключенным по умолчанию флагом. Проверенная фраза или исходный текст используются для одного поиска. Допустимый код уточнения возвращается без поиска. Контракты и отказы проверены в 68 тестах Laravel и 70 тестах FastAPI с моками. [Реализация и проверка](ai-stage-05-00-assistant.md#50-2--интерпретация-поискового-запроса-через-llm).
- [x] **5.0-3 · Сквозная проверка.** На копии 100 работ 4.4C подтверждены RU и EN нормализация с `qwen3:8b`, доступные карточки и сохранение исходной выдачи при отказе chat-модели. Проверены сессия, CSRF, каноническая ссылка и контрольные суммы данных. Этап 5.0 завершён в исследовательском контуре. [Фактические результаты](ai-stage-05-00-assistant.md#50-3--сквозная-проверка-llm-ассистента).

**Компоненты и зависимости.** Laravel routes, validation, выдача, существующий Hybrid Search, затем внутренняя операция FastAPI и Ollama. 5.0-1 зависит от подтверждённого 4.x. 5.0-2 использует проверенный контракт 5.0-1. 5.0-3 использует оба результата и сохранённый корпус. Полнота старых данных 4.1 остаётся отдельным вопросом.

**Приёмка и тесты.** Laravel-тесты проверяют сортировку и лимит, гостя, запрет доступа, пустой результат, неправильные параметры, ссылки и отсутствие индексных вызовов на запись. Тесты FastAPI с подменой Ollama проверяют схему, отказ, превышение бюджета и недоступность. В сквозном прогоне есть доступные карточки, переход открывает ту же работу, отказ LLM сохраняет работоспособный результат поиска. Используются сохранённые индексы.

**Риски и сложность.** Средняя. Начальные меры из риска 9, ограничения запросов и бюджет LLM входят в приёмку этапа. Один осмысленный запрос проверяет цепочку, качество на разных задачах измерит 5.4.

### 5.1 — RAG и контекст диалога

**Цель и результат.** Ответ формируется по актуальным источникам, а уточнение может ссылаться на предыдущий ход. Состояние недостаточности источников даёт понятное уточнение или список доступных работ.

- [x] **5.1-1 · Ответ с проверяемыми источниками.** Защищённый `POST /assistant/answer` использует существующий поиск, формирует ограниченный контекст и получает от FastAPI план из пар `source_ref` и `fact_ref`. Laravel повторно проверяет доступ и факты и собирает ответ. При ошибке генерации остаются проверенные карточки. Реализация прошла 92 теста Laravel и 113 Python-тестов с моками. [Контракт и результаты](ai-stage-05-01-rag.md#51-1--rag-ответы-с-проверяемыми-источниками).
- [x] **5.1-1R · Реальный RAG-прогон.** На копии 100 работ 4.4C подтверждены ответы `qwen3:8b` с проверяемыми фактами, те же карточки при отказе генерации и сохранность корпуса. Диагностический повтор общего EN-запроса выявил дублирование пары в плане. [Измерения и наблюдения](ai-stage-05-01-rag.md#51-1r--реальная-интеграционная-проверка-rag).
- [x] **5.1-2A · Хранение и защита истории.** Добавлены независимые таблицы диалогов и ходов, шифрование запросов, API владельца с пагинацией и каскадным удалением. История выдаёт минимальные сведения о ходе. Лимиты, доступ и сохранность контракта ассистента покрыты тестами. [Контракт и проверки](ai-stage-05-01-rag.md#51-2a--хранение-и-защита-истории-диалогов).
- [x] **5.1-2B · Сохранение ходов и контекстные уточнения.** Новый маршрут сохраняет завершённые ходы и перепроверенные цитаты. Resolver выбирает независимый поиск, уточнение по разрешённой истории или запрос уточнения. При чтении факты и ссылки восстанавливаются после проверки доступа, ревизии и значения. Прошли 145 тестов Laravel и 150 тестов FastAPI на SQLite и HTTP-моках. [Контракт и проверки](ai-stage-05-01-rag.md#51-2b--сохранение-rag-ходов-и-контекстные-уточнения).
- [ ] **5.1-2R · Сквозная проверка диалога.** На изолированной копии 4.4C подтверждены первый RAG-ход, чтение и удаление истории в MySQL, независимый поиск, отзыв доступа, fallback и конфликт конкурентных запросов. При подтверждённой дате `qwen3:8b` не выбрала `use_previous`. Laravel вернул безопасное уточнение. 5.1 остаётся открытым до подтверждения этого сценария на реальной модели. [Результаты и ограничения](ai-stage-05-01-rag.md#51-2r--реальная-интеграционная-проверка-многоходового-диалога).

**Компоненты и зависимости.** Laravel orchestration, валидация ссылок, схема хранения истории, FastAPI и Ollama. Используется контракт и доказанный сценарий 5.0. Для диалогов 5.1-2 сначала нужен надёжный вывод одного ответа в 5.1-1.

**Приёмка и тесты.** Ответ с фактами указывает минимум один текущий допустимый источник. Неизвестные ID, URL и факты от модели не попадают в ответ. Если источник изменился или исчез во время генерации, связанный текст и ссылка исключаются. Тесты включают попытки prompt injection в метаданных, чужой диалог, удаление истории, превышение бюджета, неприменимое уточнение и пустую выдачу. При отзыве прав прежние карточки и цитаты недоступны через историю.

**Риски и сложность.** Высокая. Изоляция владельцев и политика хранения входят в проектирование 5.1, их пригодность для внешнего запуска проверяет 5.5-3. Достоверность метаданных и пригодность ответа измеряются отдельно в 5.4.

### 5.2 — Структурирование медиаконтента

**Цель и результат.** Из AI-метаданных и существующего поиска формируются проверяемые тематические предложения для изображений. Результат содержит связь с исходными работами, версией модели и сценарием формирования.

- **5.2-1 · Предложения.** Найти связанные работы и предложить темы, теги, категории или состав тематической коллекции. Сохранить происхождение предложения, использованные ID, версии входов, модель, версию шаблона и время.
- **5.2-2 · Подтверждение.** Применять предложение только после явного действия пользователя или модератора с подходящим правом. Laravel перепроверяет текущую ревизию и права и выполняет изменение через штатные операции работы или коллекции. Повторное подтверждение идемпотентно.

**Компоненты и зависимости.** Допустимые метаданные Laravel, похожие работы, FastAPI для структурированного предложения, серверная модель предложения и существующие операции тегов и коллекций. Используются правила допуска 5.1-1 и API 5.0. Полная история диалога не требуется.

**Приёмка и тесты.** Предложения видны только допустимому получателю. Неутверждённое предложение не меняет работу, индекс или коллекцию. Проверяются устаревшая ревизия, чужая коллекция, отказ автоматики при отсутствии прав, происхождение и повтор подтверждения.

**Риски и сложность.** Высокая. Vision и теги могут содержать ошибки. Первую версию ограничивает тип `image`. Для видео требуется самостоятельно подтвердить транскрипты, разметку кадров и их доступную индексацию. Имеющиеся миниатюра и превью видео подтверждают только подготовку представления. [Медиа](../../app/Models/Artwork.php) · [Изменение работы](../../app/Actions/Artwork/UpdateArtwork.php) · [Операции коллекций](../../app/Http/Controllers/CollectionController.php).

### 5.3 — Интерфейс ассистента

**Порядок разработки.** Интерфейс 5.3 развивается раньше структурирования медиаконтента 5.2. Подключение многоходового режима в 5.3-2 учитывает открытый сценарий 5.1-2R.

**Цель и результат.** Vue 3 и Inertia дают диалог с поиском, ответами и доступными карточками. Карточка открывает каноническую публикацию, загрузка и ошибки понятны пользователю.

- [x] **5.3-1 · Панель поиска.** Защищённая страница `/assistant` подключена к API 5.0. Есть локальная лента, отмена, повтор и карточки с каноническими ссылками. Проверены поиск через Laravel и отдельную SQLite, переход к работе, обе темы и четыре размера экрана. [Интерфейс и проверки](ai-stage-05-03-interface.md#53-1--базовый-интерфейс-ai-ассистента).
- [x] **5.3-2 · Диалог и источники.** Подключены серверная история, RAG-цитаты, контекстные ходы и защищённые миниатюры. В исследовательском контуре подтверждены реальный ответ с источниками, повторное открытие диалога и безопасное отображение запроса уточнения. [Интерфейс и проверки](ai-stage-05-03-interface.md#53-2--диалоги-история-rag-и-источники).
- [x] **5.3-3 · Техническая доработка и визуальная полировка.** Исправлены обновление истории и миниатюр, навигация по диалогам и учёт серверного лимита ввода. Пройдены два полных Laravel-прогона, 26 JavaScript-тестов, сборка и проверка в Edge на шести размерах в обеих темах. На реальных сервисах подтверждены RAG с миниатюрами, независимый поиск, восстановление и удаление истории. Вопрос о XIX веке завершился безопасным уточнением. Положительный сценарий resolver остаётся открытым в 5.1-2R. [Результаты 5.3-3](ai-stage-05-03-interface.md#53-3--визуальная-полировка-и-подготовка-к-пользовательской-приёмке).
- [ ] **Пользовательская приёмка 5.3.** Владелец проверяет пользовательские сценарии в локальном Docker, включая переходы по источникам, физическое мобильное устройство, экранную клавиатуру и восстановление после ошибок. Этап 5.3 остаётся открытым до этой проверки. [Запуск и чек-лист](ai-assistant-manual-testing.md).

**Компоненты и зависимости.** Vue, Inertia, Laravel route/API, компоненты карточек и состояние запросов. 5.3-1 может начинаться после 5.0, 5.3-2 зависит от 5.1-2. Процесс подтверждения предложений 5.2 развивается отдельно.

**Приёмка и тесты.** Запрос, уточнение, пустая выдача, ошибка, отмена и повтор отображаются корректно. Запоздалый ответ не подменяет свежий. Карточка и источник не обходят проверку доступа. Клиентские тесты проверяют переходы состояний, клавиатуру и безопасное отображение текста. Интеграционные — отзыв доступа и отказ API.

**Риски и сложность.** Средняя. Существующая карточка может использовать URL медиа из модели. Нужны ограниченные данные и проверка доступа к превью перед подключением. [Страница поиска](../../resources/js/Pages/Search/Index.vue) · [Карточка](../../resources/js/Components/Gallery/ArtworkCard.vue).

### 5.4 — Масштабирование и качество

**Цель и результат.** Независимые отчёты по качеству retrieval и RAG, отдельные срезы RU/EN и измеренные бюджеты задержки и ресурсов.

- **5.4-1 · Retrieval.** Зафиксировать более крупный независимый корпус, критерии доступа к нему, версии моделей и коллекций. Сохранить 4.8 отдельной неизменной базой. Сравнить Dense и Hybrid и допустимые варианты reranking. Измерить nDCG@5/10, Hit@5, покрытие кандидатов и расхождения по языкам.
- **5.4-1A · Маршрутизация намерений. Завершён.** На 75 парных запросах ложные запуски поиска сократились с 44 до 2. Все 14 поисковых фраз, кандидаты и ранги совпали. Macro F1 новой маршрутизации равна 0,855. Диалоги поддерживают опциональное включение флагом. Значение по умолчанию выключено до проверки неоднозначных запросов и хвоста задержки первого поиска. [Отчёт и метрики](ai-stage-05-04-intent-routing.md).
- **5.4-1B · Структура поискового запроса. Завершён.** На 64 независимых формулировках приняты 55 структур, Exact Match 22 из 64, микро-F1 0,629 против 0,386 у простого baseline. Все 16 пар сохранили исходную фразу и ранги. Медиана дополнительной серверной задержки 857 мс. Компонент остаётся исследовательским из-за пропусков, ошибок связей и ложных уточнений. [Отчёт и метрики](ai-stage-05-04-query-understanding.md).
- **5.4-1C · Лексический и гибридный поиск. Завершён.** На 18 независимых запросах Recall@20 по известным полным совпадениям вырос с 0,690 до 0,747. Русский nDCG@5 снизился с 0,344 до 0,333, p50 retrieval вырос с 95 до 362 мс. Визуальная разметка предварительная. `AI_ASSISTANT_LEXICAL_METADATA_ENABLED` остаётся выключенным по умолчанию. [Отчёт и метрики](ai-stage-05-04-hybrid-search.md).
- **5.4-1D-1 · ColBERT и ранжирование кандидатов. Завершён.** На основном каталоге проверены Dense, штатный и экспериментальный Hybrid и три схемы ColBERT. Глубина 20 выбрана на development. ColBERT после RRF дал предварительный прирост на регрессии 5.4-1C, который не подтвердился на 40 независимых формулировках. Режим выключен по умолчанию. Подготовлены слепые пулы до топ-20 для человеческой проверки. [Отчёт и метрики](ai-stage-05-04-colbert-reranking.md).
- **5.4-1D-2 · Ранжирование с учётом условий. Запланирован.** Использовать выводы 5.4-1B и различать подтверждение, противоречие и недостаточность доказательств. Палитра описывает оттенки изображения. Для цвета фона, привязки к предмету, точного количества и пространственного отношения требуется подходящее явное свидетельство.
- **5.4-1D-3 · Человеческая проверка и итоговая конфигурация. Запланирован.** Оценить слепые пулы 5.4-1D-1 и проверить результаты учёта условий. Выбрать конфигурацию по независимой разметке, покрытию по глубинам, срезам RU/EN и затратам задержки. Сохранить отдельную базу 4.8.
- **5.4-2 · RAG и нагрузка.** Оценить подтверждённость фактов и ссылок, корректность отказов, качество уточнений и уместность ответа отдельно от ранжирования. Замерить p50/p95, ошибки и насыщение GPU/RAM при конкуренции запросов, отдельно для холодного и прогретого состояния. Разобрать неудачные случаи по слоям.
- **5.4-2A · Визуальный контекст RAG. Завершён.** `legacy` остаётся штатным режимом. `visual_priority` сохранён для исследований. [Парное сравнение](ai-stage-05-04-rag-context.md).
- **5.4-2B · Качество ответов RAG. Запланирован.** На фиксированных кандидатах проверить выбор фактов, корректность ссылок, полноту ответа и поведение при недостатке подтверждённых данных. Измерить вклад composer в задержку и разобрать ошибки по слою, где они возникли.
- **5.4-2C · Многоходовой контекст.** Уточнить привязку к ранее показанным работам и обработку продолжений. В 5.4-1A использован прежний resolver и его проверенные ссылки.

**Компоненты и зависимости.** Новые исследовательские артефакты, стенд нагрузки и наблюдаемость Laravel/FastAPI. Для retrieval достаточно работоспособного 5.0. Для оценки ответов нужен 5.1, для пользовательских замеров — интерфейс 5.3. Стабильный манифест моделей и корпуса нужен до измерения.

**Приёмка и тесты.** Раздельные воспроизводимые отчёты и фиксированные входы. На сравнимом корпусе указаны условия теста, настройки, язык, ограничения и критерии допуска. Тесты проверяют расчёт метрик, воспроизводимость, соблюдение бюджета нагрузки и деградацию под отказом. Числовые целевые SLO определяются по назначению выпуска и данным измерений.

**Риски и сложность.** Высокая. Эффект на 40 прежних запросах не распространяется автоматически на новый корпус. Для сравнения ColBERT требуется допустимый режим модели. [Неизменная оценка 4.8](ai-stage-04-08-evaluation.md).

### 5.5 — Надёжность и подготовка production

**Цель и результат.** Определённая область выпуска защищена от просроченных операций, пропусков и нарушений доступа. Проверены эксплуатация, политика данных и права на модели.

- **5.5-1 · Надёжная запись и обработка.** Передавать ревизию в операциях индекса и проверять ожидаемое состояние на стороне обработчика. Защитить Qdrant от поздних upsert/delete и Laravel–ColBERT от конфликтов при изменении публикации. Согласовать дедлайны и завершение зависших записей операций. Доставлять намерения из долговременного журнала с дедупликацией и безопасным повтором. Проверять совместимость версии embedding и параметров коллекции.
- **5.5-2 · Сверка и диагностика.** Сделать ограниченную read-only инвентаризацию обеих сторон, включая неизвестные Laravel ID. Ввести периодическую сверку с наблюдаемыми результатами и ограниченным восстановлением в подтверждённой области. Учесть историческую сверку 4.1 и отдельное согласование любых изменений рабочих данных.
- **5.5-3 · Допуск и эксплуатация.** Проверить обязательную авторизацию используемых служебных API, сеть, ключи и их ротацию, журналирование, доступ к оригиналам и превью, историю и её срок хранения. Зафиксировать лицензии моделей. Проверить нагрузку, алерты и отказ LLM с сохранением поиска.

**Компоненты и зависимости.** Laravel Queue и журнал операций, FastAPI, Qdrant, ColBERT при его использовании, службы доступа и эксплуатационная конфигурация. 5.5-2 использует гарантии записи 5.5-1 перед включением автоматического восстановления. Требования доступа из 5.5-3 начинают применяться уже в 5.0–5.3. Результаты 5.4 дают критерии нагрузочной готовности.

**Приёмка и тесты.** Тесты поздней записи и удаления, потери очереди, конкурирующего изменения и аварийного завершения проходят с реальными сервисами в тестовом контуре. Периодическая сверка обнаруживает расхождение и оставляет объяснимый журнал. Проверки доступа включают неправильные ключи, доступ из недопустимой сети, чужую историю, приватность и прямые пути выдачи медиа. Наблюдаемость позволяет отличить потерю сообщения, timeout, отказ модели и недоступный источник. Закрытие каждого применимого P0 требует результата испытаний.

**Риски и сложность.** Высокая. Работы с P0 планируются до соответствующего запуска, даже при параллельной разработке 5.0–5.4. Операции восстановления исторических данных требуют отдельной приёмки этапа 4.1. [Риски и блокировки](#6-матрица-рисков).

### 5.6 — Финальные испытания и выпуск

**Цель и результат.** Проверенный полный сценарий и формальное решение о допустимой области запуска с инструкциями развёртывания, эксплуатации и отката.

- **5.6-1 · Связанный прогон.** Проверить авторизацию, поиск, ответ и уточнение, источники, отзыв доступа, деградацию поиска и генерации, мониторинг и восстановление. Повторить регрессии индексов, API и UI. Если 5.2 входит в выпуск, дополнительно проверить подтверждение предложения и журнал происхождения.
- **5.6-2 · Решение и документация.** Описать проверенную конфигурацию, флаги, модели, инструкции запуска, отката и операции сопровождения. Зафиксировать решение о локальном, ограниченном внешнем или production-режиме для конкретной сборки.

**Компоненты и зависимости.** Контур выбранной конфигурации, документация и учёт результатов. Нужны завершённые сценарии 5.0–5.3 в области выпуска, измерения 5.4 и доказательства применимых условий 5.5.

**Приёмка и тесты.** Полная регрессия и сквозной сценарий проходят, утверждённые критерии задержки и безопасности соблюдены. Сбой отдельного компонента и откат проверены. Решение о выпуске опирается на свидетельства по каждому блокирующему условию.

**Риски и сложность.** Высокая. Масштаб выпуска ограничен подтверждёнными данными, лицензиями, доступами и профилем нагрузки. При открытом блокере соответствующая конфигурация остаётся исследовательской.

## 7. План первого прототипа 5.0-1

### Входные условия и границы

1. Использовать отдельный локальный Docker-контур с согласованным снимком 4.4C из 100 изображений. Проверить, что MySQL, Qdrant, Laravel и FastAPI используют тестовые копии или read-only доступ, а Ollama использует совместимую embedding-модель. Перед стартом FastAPI проверить наличие и имя коллекции, чтобы readiness не создала пустую коллекцию вместо ожидаемого снимка. Рабочие базы, очереди и исторические артефакты находятся вне контура. Воркеры индексации и планировщик для этой проверки не требуются. [Корпус 4.4C](ai-stage-04-04-dataset.md#44c--100-изображений).
2. Подтвердить доступность существующего Hybrid Search контрольным чтением. В контуре включён AI-сервис, `AI_RERANK_ENABLED=false`, синхронизация ColBERT выключена. Доступ выдаётся тестовой учётной записи. Fallback к LIKE сохраняется. Начальный доступ к LLM ограничивается созданием embedding поисковой фразы.
3. Использовать Laravel-сессию и CSRF для браузерного запроса, проверенную учётную запись и выключенный по умолчанию флаг ассистента. Служебные API внутри контура требуют ключей для используемых маршрутов. В 5.0-1 журнал fallback ограничен типом исключения. Лексический fallback сохранён. [Обработчик fallback](../../app/Services/Search/HybridSearchService.php).

### Контракт API

Маршрут `POST /assistant/search` находится в существующей защищённой группе веб-маршрутов Laravel с `auth:sanctum`, проверенной веб-сессией, подтверждённым email и CSRF. Клиент отправляет JSON. При включённом флаге маршрут доступен подтверждённой учётной записи в изолированном контуре. Квота — 10 запросов в минуту на пользователя. Ограничение тела — 4 КиБ. Ответы используют `Cache-Control: private, no-store`. [Группа веб-маршрутов](../../routes/web.php).

```json
{
  "query": "Найди изображения птиц у воды",
  "limit": 10
}
```

Разрешены поля `query` и `limit`. `query` после trim содержит 1–500 символов. `limit` — целое число 1–20, значение по умолчанию 10. Тип поиска задаёт сервер, `image`. Пользователь не передаёт ID источников, URL и параметры выборки закрытых работ.

```json
{
  "status": "ok",
  "results": [
    {
      "artwork_id": 441055,
      "title": "Bird with Pink Plumage",
      "url": "/artworks/441055"
    }
  ]
}
```

Ответ иллюстрирует формат. В проверке 5.0-3 работа `441055` заняла первое место по исходной RU-фразе и второе после нормализации. [Фактические результаты](ai-stage-05-00-assistant.md#50-3--сквозная-проверка-llm-ассистента).

| Ситуация | Ответ |
| --- | --- |
| Найдены доступные работы | HTTP 200, `status=ok`, упорядоченные карточки. |
| Существующий поиск и фильтры вернули пустую выдачу | HTTP 200, `status=no_results`, `results=[]`. Текущий Hybrid уже преобразует семантический отказ в попытку лексического поиска. |
| Запрос отклонён | JSON 419 при ошибке CSRF, 401 для гостя при валидном CSRF, 403 для аутентифицированной записи без допуска, 404 при выключенном флаге для допущенного пользователя, 413 при превышении размера, 422 при неверных полях, 429 при превышении квоты. |
| Проверку актуальных записей или прав нельзя завершить | Безопасный 503 без списка кандидатов и деталей внутренних исключений. |

### Последовательность реализации и проверки

1. Добавить маршрут и тесты в Laravel. Вызвать `HybridSearchService::search` с `type=image`, первой страницей и `perPage=20`. Сохранить настройки ранжирования приложения. При текущих настройках каждая ветка получает до 50 кандидатов, а адаптер ассистента перепроверяет не более 20 верхних работ. Прототип работает на стандартных ограниченных настройках этого контура.
2. Перечитать кандидатов одним запросом по ID через актуальное подключение MySQL. Применить `publiclyVisible()` с действующим глобальным фильтром блокировки, тип изображения, существование медиа и `ai_indexing_enabled=true`. Применить `ArtworkPolicy::view` в контексте пользователя. Сохранить порядок оставшихся ID и отсечь по `limit`. Собрать минимальный набор полей и относительный URL через именованный маршрут `artworks.show`. Маршрут карточки самостоятельно проверяет доступ. Прямые URL файлов и метаданные в этот контракт не включены.
3. В изолированных тестах подменить AI-HTTP и Qdrant-кандидатов. Передать застарелые ID приватной, заблокированной, снятой с публикации или удалённой работы, заблокированного автора, видео и записи с выключенной индексацией. Подтвердить исключение каждого. Проверить отзыв доступа между первичным и итоговым чтением, валидный путь карточки, правила валидации и пустой ответ. При отказе Dense проверить лексический fallback. По журналу запросов и снимку БД подтвердить отсутствие записи в таблицы работ, AI-метаданных и индексы.
4. Завершить 5.0-1, когда маршрут возвращает проверенный список по тестовой фразе и допускает запуск в изолированном контуре с выключенным ColBERT. Для реального smoke 5.0-3 заранее закрепить вручную релевантные работы из оригиналов 4.4C. По фразе «Найди изображения птиц у воды» должен вернуться доступный список с хотя бы одной подтверждённой релевантной работой в пределах 10 результатов и ссылками на те же ID. Неудача фиксируется как наблюдение, ранжирование не настраивается по этому единственному запросу.

## 8. Ограничения исследовательской и production-версий

**Исследовательский режим.** Изолированный запуск и только разрешённые данные. 5.0 использует публичные изображения и сохранённый индекс. Диалоговая история появляется в 5.1, предложения изменений — в 5.2. ColBERT выключен по умолчанию. Эксперименты с `jinaai/jina-colbert-v2` допустимы в рамках подтверждённого некоммерческого режима. [Итог 4.x](ai-stage-04-09-final.md).

**Внешний и production-режим.** Нужны подтверждённые применимые P0, критерии выпуска 5.6 и эксплуатационное решение по оставшимся рискам. Защита доступа распространяется на оригиналы, превью, дочерние ссылки и сохранённую историю. Коммерческий сценарий может использовать Dense + LIKE сразу после прохождения остальных применимых условий. Подключение ColBERT зависит от проверенных прав либо выбранной альтернативы. Закрытие 4.9 фиксирует готовность плана, исторические задачи 4.1 продолжаются отдельно. [Открытая сверка 4.1](ai-stage-04-01-reconciliation-audit.md).
