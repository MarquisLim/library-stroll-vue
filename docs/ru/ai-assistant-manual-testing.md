# Ручная приёмка Library Stroll AI

Инструкция предназначена для владельца проекта. Проверка проводится на ветке `docker` в локальном Docker с уже проиндексированными изображениями. Используйте рабочие локальные данные или их подготовленную копию с MySQL, Qdrant и Media Library. Архивные исследовательские тома и production для приёмки не используются. [Результаты технических проверок](ai-stage-05-03-interface.md#53-3--визуальная-полировка-и-подготовка-к-пользовательской-приёмке).

## Запуск в Windows

**1. Выберите локальный проект и проверьте его тома.** Откройте PowerShell в корне репозитория и запустите Docker Desktop. Сверьте имя локального проекта с `COMPOSE_PROJECT_NAME` в `docker/.env` и с уже существующими томами.

```powershell
git branch --show-current
docker compose ls -a
docker volume ls
```

Если `docker/.env` отсутствует, создайте его командой ниже. При использовании существующих данных сохраните имя проекта, настройки MySQL, имя коллекции Qdrant, локальные порты и действующие секреты. Для открытия зашифрованной истории нужен прежний `APP_KEY`. Смена имени Compose-проекта сама по себе подключит другие тома. [Общее руководство по Docker](docker.md).

```powershell
.\scripts\docker.ps1 init -Ollama host
```

**2. Настройте ассистента.** В `docker/.env` включите функции для локальной приёмки. Значения моделей ниже соответствуют исследовательскому прогону. Если текущая локальная коллекция создана другой embedding-моделью, сохраните конфигурацию той модели, которой построены её векторы.

```dotenv
DOCKER_OLLAMA_MODE=host
OLLAMA_BASE_URL=http://host.docker.internal:11434
OLLAMA_CHAT_MODEL=qwen3:8b
OLLAMA_EMBEDDING_MODEL=qwen3-embedding:0.6b
OLLAMA_VISION_MODEL=qwen3-vl:4b
AI_SERVICE_ENABLED=true
AI_ASSISTANT_ENABLED=true
AI_ASSISTANT_RAG_ENABLED=true
AI_ASSISTANT_HISTORY_ENABLED=true
AI_ASSISTANT_CONTEXT_ENABLED=true
AI_ASSISTANT_LLM_ENABLED=false
AI_RERANK_ENABLED=false
AI_COLBERT_SYNC_ENABLED=false
AI_COLBERT_AUTO_SYNC_ENABLED=false
```

Проверьте наличие непустого `AI_SERVICE_API_KEY` в том же файле. Laravel и FastAPI читают общий локальный `docker/.env`. Секреты оставьте в локальной конфигурации. Если меняете порт приложения, приведите `APP_URL` в соответствие с `APP_PORT`.

**3. Проверьте Ollama на Windows.** Запустите установленную Ollama и проверьте, что она отвечает и видит теги из вашей конфигурации. Для диалога нужны chat- и embedding-модели. Общая проверка готовности проверяет также настроенную Vision-модель.

```powershell
Invoke-RestMethod 'http://127.0.0.1:11434/api/version'
ollama list
```

**4. Проверьте MySQL и Qdrant перед запуском ассистента.** Поднимите только хранилища выбранного локального проекта. В команде проверки Qdrant укажите фактические `QDRANT_PORT` и `QDRANT_COLLECTION` из `docker/.env`.

```powershell
.\scripts\docker.ps1 up -Ollama host mysql qdrant
.\scripts\docker.ps1 status

$qdrantPort = 6335
$collectionName = 'librarystroll_artworks'
(Invoke-RestMethod "http://127.0.0.1:$qdrantPort/collections/$collectionName").result |
    Select-Object status, points_count
```

Убедитесь, что MySQL использует ожидаемый существующий том и находится в состоянии `healthy`. Коллекция Qdrant должна существовать и содержать точки. FastAPI может создать пустую коллекцию при старте, поэтому проверка до запуска помогает выявить ошибочное имя. Если том новый, коллекция отсутствует или пуста, сначала сверьте проект и конфигурацию с имеющимися локальными данными. Повторный импорт и массовая переиндексация для обычной приёмки не нужны.

**5. Соберите интерфейс и запустите приложение.** Команда собирает образы PHP, Nginx и FastAPI. Dockerfile выполняет `npm ci` и `npm run build`. Для приёмки используется сборка из образа. Явный список сервисов запускает приложение без индексирующих воркеров и Scheduler. Если они уже работали в выбранном локальном проекте, продолжите проверку в подготовленной копии или отдельно остановите эти сервисы в проекте приёмки.

```powershell
.\scripts\docker.ps1 up -Ollama host web ai-api
.\scripts\docker.ps1 status
.\scripts\docker.ps1 artisan migrate:status
.\scripts\docker.ps1 artisan ai:health
.\scripts\docker.ps1 artisan ai:status --errors=0
```

Локальный сервис `init` применяет миграции при запуске. В `migrate:status` миграция `2026_11_23_100000_create_assistant_history_tables` должна быть отмечена как выполненная. Если после проверки остались ожидающие миграции, сначала убедитесь, что подключена нужная локальная MySQL. Затем выполните `.\scripts\docker.ps1 artisan migrate --force` и повторите `migrate:status`.

`ai:health` проверяет доступность AI-сервиса из Laravel. Если он сообщает об ошибке Ollama, проверьте `OLLAMA_BASE_URL` и наличие настроенных тегов. Недоступность chat-модели может сделать общий `/ready` неготовым даже при работающем Dense Search. `ai:status` показывает состояние AI-индексации в MySQL. Перед приёмкой убедитесь, что там есть проиндексированные работы, соответствующие точкам Qdrant, и откройте публичное изображение в галерее, чтобы проверить Media Library.

**6. Откройте ассистента.** Войдите через `/login` под существующим локальным пользователем с подтверждённым email (`users.email_verified_at` заполнено). Используйте один хост для входа и дальнейшей работы, чтобы браузер отправлял ту же cookie-сессию. При стандартном `APP_PORT=8088` откройте [вход](http://localhost:8088/login), затем выберите «AI-ассистент» в навигации или перейдите на [страницу ассистента](http://localhost:8088/assistant).

## Чек-лист

Используйте отдельный тестовый разговор и проходите строки по порядку. Для каждого сценария запишите «пройдено», «не пройдено» или «не проверено». При расхождении запишите наблюдаемый результат, шаг воспроизведения, браузер и устройство. Сохраняйте снимки без секретов и личных данных.

| Сценарий | Действие | Ожидаемый результат |
| --- | --- | --- |
| Создание диалога | Нажмите «Новый диалог» и отправьте «Найди изображения птиц у воды». | Открывается пустой экран. После первой отправки появляется отдельный разговор с подписью из первого сообщения и группой по времени последней активности. |
| Поиск изображений | Проверьте карточки в ответе на запрос о птицах у воды. | При наличии подходящих изображений ассистент показывает доступные работы. Конкретные ID зависят от локального корпуса. При пустой выдаче ассистент сообщает, что не нашёл подходящих изображений. |
| RAG-ответ | Прочитайте ответ на первый запрос и сопоставьте несколько фрагментов с работами. | У каждого показанного фрагмента есть ссылка на его источник. При недостатке подтверждённых данных ассистент сообщает об этом. При отказе генерации он может показать проверенные карточки без объяснения. Чтобы принять RAG, зафиксируйте хотя бы один успешный ответ с подтверждёнными фрагментами. |
| Миниатюры | Проверьте картинки в карточках. Если в тестовых данных есть работа без миниатюры, проверьте и её. | Миниатюры сохраняют пропорции. Если безопасное превью недоступно, показана заглушка, а ссылка на доступную публикацию остаётся. |
| Переход к источнику | Откройте ссылку `[1]` рядом с фактом и действие открытия работы на карточке. | Открываются канонические страницы `/artworks/{id}` соответствующих работ. Прямой URL файла не используется. |
| Контекстное уточнение | В том же разговоре отправьте «А какие из них относятся к XIX веку?». | Сообщение добавляется к тому же разговору. При нехватке сведений допустимы просьба уточнить или сообщение о недостатке данных. Название и визуальный стиль работы сами по себе не подтверждают дату. Положительный сценарий с подтверждённой датой остаётся открытым в 5.1-2R. |
| Независимый запрос | После уточнения отправьте «Покажи горные пейзажи» в том же разговоре. | Поиск снова использует каталог. При наличии подходящих работ выдача может включать публикации за пределами ответа про птиц. |
| Восстановление истории | Перезагрузите страницу, откройте разговор из панели и переключитесь между двумя своими диалогами. Для длинного разговора подгрузите ранние ходы. | Ходы восстанавливаются в хронологическом порядке без дублей. При подгрузке сохраняется место чтения. Переключение не подмешивает чужие сообщения, а отозванные источники отсутствуют на заново прочитанной странице истории. Карточки ответа, который был выдан без сохранённых цитат, могут отсутствовать после перезагрузки. |
| Светлая и тёмная темы | Проверьте начальный экран, длинную ленту и карточки в обеих темах. Пройдите элементы Tab. | Текст и активный диалог различимы. Фокус видим на кнопках и ссылках. Длинные названия и запросы переносятся без горизонтальной прокрутки. |
| Мобильный интерфейс | Проверьте узкий экран и по возможности физический телефон. Откройте панель истории, выберите разговор, вызовите экранную клавиатуру. С подключённой клавиатурой проверьте Escape. | Панель закрывается после выбора, по нажатию вне неё и по Escape. При закрытии без выбора фокус возвращается к кнопке истории. Поле ввода и отправка остаются доступны над нижней навигацией и клавиатурой. |
| Ошибка и отмена ожидания | Отправьте запрос в тестовом диалоге и нажмите «Отменить ожидание». Для проверки сетевой ошибки временно включите Offline в DevTools, затем восстановите связь. | Предыдущие сообщения сохранены. Интерфейс предлагает обновить историю перед повтором. POST не повторяется автоматически. Если исход операции неизвестен, интерфейс не утверждает, что сообщение точно сохранено или потеряно. |
| Конфликт или превышение квоты | Если при работе в двух вкладках возникнет конфликт, проверьте уведомление. Если при обычном использовании достигнут лимит, дождитесь восстановления квоты. | При 409 интерфейс обновляет историю и объясняет конфликт. При 429 показывает сообщение об ограничении. Повтор возможен по явному действию пользователя. |
| Удаление | Отмените первое подтверждение удаления, затем повторите и подтвердите. | После отмены диалог остаётся в списке. После подтверждения тестовый диалог исчезает и больше не открывается. Другие диалоги сохранены. |

Физический телефон должен иметь доступ к отдельному тестовому адресу. Стандартный локальный Compose публикует сайт только на loopback, поэтому для этого запуска используйте эмуляцию узкого экрана в браузере. Проверку на физическом телефоне запланируйте в контролируемом тестовом контуре.

После приёмки удалите тестовые диалоги. Если локальный проект запускался специально для проверки, его можно остановить командой `.\scripts\docker.ps1 down`. Тома сохраняются.
