# Исследовательский датасет Library Stroll

Дата: **11 ноября 2026 года**. Этап 3 — подготовка данных для диссертации «Разработка интеллектуального ассистента для семантического поиска и структурирования медиаконтента на основе LLM».

Это подготовка корпуса, запросов и независимых оценок, а не эксперимент поиска. Команды не запускают AI, embeddings, Ollama, Qdrant, обучение или расчёт метрик. Существующие поисковые алгоритмы и импорт не меняются. Миграций для этого этапа нет.

## Демонстрационный каталог и исследовательский набор

`demo:populate` создаёт публикации и ведёт `storage/app/demo-import/manifests/balanced-42.json`. Research Dataset только читает существующие записи и медиа; его файлы находятся в `storage/app/research-datasets/`. Он не редактирует публикации, профили, теги, коллекции, AI-флаги или demo-manifest и не исправляет повреждения автоматически.

Исследовательский набор содержит один общий корпус для всех будущих вариантов поиска. Разделение development/evaluation относится к запросам, а не изображениям. Основной ID — `source:external_id`; `artwork_id` и Spatie media ID — дополнительные локальные ссылки, которые могут отличаться при восстановлении на другой БД.

Команды разрешены в `local`/`testing`. Каталог сначала проверяется `demo:verify`, затем отдельным селектором исследовательской системы. Ошибки файлов/метаданных исключают объект; ограничения и недобор сохраняются в отчёте. Неизвестный оригинальный автор допустим для PD/CC0. Для CC BY обязательны достоверный автор и атрибуция.

## Запуск из Windows / Docker

Откройте PowerShell в корне проекта. Перед обновлением контейнеров дождитесь завершения текущего импорта. После установки обновлённого кода:

```powershell
.\scripts\docker.ps1 up
.\scripts\docker.ps1 artisan demo:verify
.\scripts\docker.ps1 artisan dataset:prepare --name=research-pilot --size=25 --seed=42 --preset=balanced --dry-run
.\scripts\docker.ps1 artisan dataset:prepare --name=research-pilot --size=25 --seed=42 --preset=balanced
.\scripts\docker.ps1 artisan dataset:validate --name=research-pilot
```

Пилот проверяет процедуру, но не соответствует минимальному научному размеру по умолчанию. `dataset:prepare` сохраняет **черновик**, даже если каталог неполон; сообщает фактическое число объектов. `dataset:validate` возвращает код 1, пока корпус/запросы/разметка не готовы, и объясняет причину. Это не свидетельствует само по себе о неисправности Docker.

После завершения полноценного каталога:

```powershell
.\scripts\docker.ps1 artisan dataset:prepare --name=library-stroll-v1 --size=350 --seed=42 --preset=balanced --dry-run
.\scripts\docker.ps1 artisan dataset:prepare --name=library-stroll-v1 --size=350 --seed=42 --preset=balanced
```

`--size` — общий целевой размер корпуса, 1–5000. По умолчанию только изображения; `--include-videos` разрешает добавить видео в этот общий размер. Видео требуют настоящих оригинала, миниатюры, превью, соответствия source media ID и положительной длительности/видеопотока по FFprobe. Анализа содержания видео нет.

`--seed` — seed отбора, а не ограничение seed импортёра: берутся пригодные demo-импорты указанного preset. Старые записи без `dataset_preset` относятся к balanced. Работы других preset не переносятся. Для повторного запуска с теми же данными/параметрами существующий черновик сохраняется вместе с ручной работой.

Если исходные данные/правила изменились, команда отказывается молча заменить черновик. Используйте новое имя или явно архивируйте старый через `--refresh`:

```powershell
.\scripts\docker.ps1 artisan dataset:prepare --name=library-stroll-v1 --size=350 --seed=42 --preset=balanced --refresh
```

Предыдущий draft останется в `archives/`, ручные оценки автоматически не переносятся. Готовые versions не изменяются. Полезно сохранять новый научный корпус только после окончания импорта: черновик, созданный при неполном каталоге, нельзя признать окончательным задним числом без нового снимка.

## Отбор и воспроизводимость

Селектор проверяет публичность, владельца/блокировки, происхождение, лицензию, текст, теги и доступность файлов. Проверяет сохранённый SHA-256 оригинала и настоящую миниатюру, исключает точные дубликаты. Повреждения не восстанавливает. Видео исключены по умолчанию.

Сначала целевые тематические доли масштабируются из demo-preset. Затем детерминированный жадный отбор балансирует категории и частоты источников, оригинальных авторов, техник, доступных дат/периодов, ориентаций и типов медиа. При равных условиях используется SHA-256 от `seed:source:external_id`, а не случайный порядок SQL или локальный ID. Одинаковый seed и одинаковый снимок дают одинаковый состав независимо от входного порядка.

Недостаток категории отражается отдельно. Остаток размера может заполняться доступными объектами других категорий без переименования их тем. Жёсткое равенство источников/авторов не гарантируется при неравном исходном каталоге; высокая концентрация источника вызывает предупреждение. Алгоритм не пытается выдумать недостающие свойства или скрыть тематический перекос.

Техника определяется только по явному слову из исходных материала/тегов. Период — техническая корзина века первого указанного четырёхзначного года, не искусственно восстановленная датировка. Оригинальная строка даты сохраняется. Неизвестные признаки остаются `null`. Ориентация вычисляется по размерам оригинала. Отбор не гарантирует баланса цветов или эстетического сходства; perceptual hash не добавлялся.

## Структура файлов и данных

```text
storage/app/research-datasets/<name>/
  .lock
  draft/
    manifest.json
    artworks.jsonl
    queries.jsonl
    pool.jsonl
    judgments.csv
    judgment-context.json
    artworks.csv
    annotation-template.csv
    annotation.html
  archives/draft-<timestamp>/
  versions/1.0/
    <те же артефакты>
    validation.json
    checksums.sha256
    README.md
  reports/
```

JSONL — один UTF-8 JSON-объект на строку. В `artworks.jsonl` сохраняются:

- `dataset_item_id`, `artwork_id`, `source`, `external_id`, `media_type`;
- название, описание, оригинальный автор, тема и теги;
- лицензия, лицензионная ссылка, исходная страница, адрес исходного медиа, атрибуция;
- SHA-256 (`media_sha256`, для изображений также `image_sha256`);
- `source_metadata`: доступные сохранённые исходные название/описание/автор/дата/материал/язык/теги и безопасный whitelist provider-метаданных;
- `normalized_metadata`: текущие название/описание/теги и статусы публикации Laravel;
- `strata`: воспроизводимые признаки отбора;
- `media`: локальные media ID/UUID, разрешённый disk, относительные пути оригинала/миниатюры, её SHA-256, URL превью, размеры, MIME, длительность и сведения о видеопревью, если есть;
- дата импорта.

Не все адаптеры исторически сохраняли необработанные теги или исходный заголовок. Если их нет, система не выдаёт текущие поля за доказанно оригинальные: `source_metadata` остаётся неполным; `tags_origin=importer_normalized_fallback` явно обозначает fallback и даёт предупреждение. Даже `stored_source_metadata` означает сохранённый импортёром снимок, а не обещание полного исходного API-ответа: музейный `SourceTags` мог уже нормализовать теги. Для строгого исследования этот факт нужно указать как ограничение исходной выборки.

AI-таблица не используется при экспорте. Исходные и нормализованные поля не смешиваются с будущим AI-обогащением. Нет email, паролей, биографий, локальных user ID или API-ключей. Публичные имена оригинальных авторов и обязательная лицензионная атрибуция сохраняются как provenance. Медиа не копируются и не добавляются в Git.

Разрешены только ссылки HTTPS без credentials/небезопасных IP; локальные пути ограничены разрешённым диском, без обхода директорий и выхода через symlink. Внешние ссылки при подготовке не скачиваются. HTML экранирует метаданные; изображения в annotation.html загружаются с локального приложения.

## Поисковые запросы

Цель — 100 черновых RU/EN-запросов (допустимый научный диапазон по умолчанию 80–120). Генератор сначала изучает выбранные категории и подтверждённые слова метаданных: только представленные понятия, совместно встречающиеся признаки и известные техники допускаются в черновик. Он не создаёт по одному запросу из точного названия каждого изображения. Если материала мало, запросов будет меньше, и это заблокирует окончательную фиксацию.

Типы: `simple`, `thematic`, `complex`, `descriptive`, `cross_lingual`; распределение зависит от корпуса и показывается в отчёте, ровно 20 каждого не гарантируется. Сложные запросы включают сочетания признаков, акварельную технику; исторические парусники с исключением современных фотографий предлагаются только при подходящих исходных свидетельствах. Метаданные помогают сформировать вопрос, но не доказывают релевантность изображения.

Каждый объект содержит `query_id`, `intent_id`, `text`, `language`, `type`, `base_type`, `split`, подсказки для пула, `reviewed=false`, `status=draft`. RU/EN-эквиваленты имеют общий intent и один split. Разделение детерминировано по группам намерений: около 25% development / 75% evaluation. Членство групп фиксируется в manifest.

Эксперт должен прочитать и исправить формулировки в `draft/queries.jsonl` **до разметки**, проверить эквивалентность RU/EN и установить `reviewed=true` (можно также `status=reviewed`). Сохраняйте ID/intent/split; изменение членства будет ошибкой. Для изменения самого плана запросов подготовьте новый draft через настройки/новое имя. Это не автоматическая экспертная проверка.

После начала разметки текст, язык, intent и split запроса связаны с оценками контрольной суммой в `judgment-context.json`. Изменение вопроса делает прежние оценки непригодными и блокирует фиксацию. Обновление одного признака `reviewed` смысл запроса не меняет.

## Независимая ручная разметка

Экспорт материалов:

```powershell
.\scripts\docker.ps1 artisan dataset:annotations --name=library-stroll-v1
```

Откройте `annotation.html` для списка запросов и локальных превью, `artworks.csv` для ID/ссылок. Скопируйте `annotation-template.csv` в отдельный `filled-expert-1.csv`: экспортируемый шаблон пересоздаётся, его нельзя использовать как единственное место сохранения незагруженной ручной работы. JSON/CSV находятся в private storage контейнера. Их можно получить без изменения каталога:

```powershell
docker compose --env-file docker/.env -f compose.yaml cp app:/var/www/html/storage/app/research-datasets/library-stroll-v1/draft ./research-review
# После ручного заполнения локального CSV:
docker compose --env-file docker/.env -f compose.yaml cp ./research-review/filled-expert-1.csv app:/var/www/html/storage/app/research-datasets/library-stroll-v1/filled-expert-1.csv
.\scripts\docker.ps1 artisan dataset:annotations --name=library-stroll-v1 --import=/var/www/html/storage/app/research-datasets/library-stroll-v1/filled-expert-1.csv
```

Если редактировали `queries.jsonl` локально, скопируйте его обратно в draft **до** заполнения/импорта оценок. Не изменяйте version-файлы. Путь `research-review` содержит исследовательские артефакты, не оригинальные изображения; храните его вне Git.

CSV:

```csv
query_id,dataset_item_id,relevance,annotator_id,judged_at
q-<id>,met:<external_id>,3,expert_1,2026-11-11T10:00:00Z
q-<id>,commons:<external_id>,0,expert_1,2026-11-11T10:03:00Z
```

Подставляйте реальные ID из файлов, не буквальные placeholders. `judged_at` можно не заполнять: при импорте сохранится UTC-время загрузки оценки. Используйте псевдоним разметчика (`expert_1`), не email или ФИО.

| Балл | Смысл |
|---|---|
| 0 | Не соответствует запросу |
| 1 | Слабо соответствует |
| 2 | Частично соответствует |
| 3 | Полностью соответствует |

Разметчик должен независимо посмотреть изображение и оценить весь запрос, включая отрицания и дополнительные признаки. Например, для «горы и озеро» один лес — 0, холмы — 1, горы без озера — 2, горы с озером — 3. Теги, категория, заголовок, позиция в лексической выдаче и будущий LLM не являются эталоном.

Пустой relevance означает `unjudged` и не записывается как 0. Импорт проверяет ID, диапазон, календарное время, псевдоним и дубликаты `(query,item,annotator)` целиком до записи. Повтор одинаковой оценки идемпотентен; конфликтующая переоценка тем же экспертом отклоняется без перезаписи. Ошибки в уже импортированной разметке следует исправлять в архивируемом/новом draft с явной записью причины, а не скрытым автоматическим обновлением.

Можно импортировать нескольких экспертов. Разногласия не усредняются автоматически: они блокируют готовность до явной человеческой adjudication с псевдонимом `adjudicator` (настраивается). Исходные оценки сохраняются. Минимум разметчиков по умолчанию 1; для диссертации разумно заранее установить 2 и описать процедуру согласования, до начала финальной разметки.

## Пул кандидатов и его смещение

Полные 350 × 100 = 35 000 пар не обязательны. Начальный пул — 30 объектов на запрос: существующий SQL LIKE по title с порядком likes_count (без вызова hybrid/AI), исходная тема/понятия, случайные объекты и другие тематические группы. Выдача ограничена фиксированным корпусом. Для каждой пары сохраняются методы включения. Это подбор для просмотра, не автоматические оценки.

Поле `initial_status=unjudged` описывает момент включения в пул. Актуальный статус определяется только по ручным строкам `judgments.csv` и политике согласования, а не по этому полю или совпадению метаданных.

```powershell
.\scripts\docker.ps1 artisan dataset:pool --name=library-stroll-v1 --size=40
# Полный пул: size >= размера корпуса
.\scripts\docker.ps1 artisan dataset:pool --name=library-stroll-v1 --size=350
# Позднее: добавить результаты другой системы, не запуская её этой командой
.\scripts\docker.ps1 artisan dataset:pool --name=library-stroll-v1 --size=40 --extend=/var/www/html/storage/app/research-datasets/library-stroll-v1/extra-pairs.jsonl
```

Строка расширения: `{"query_id":"q-...","dataset_item_id":"met:...","method":"future_vector_pool"}`. Все ID проверяются. Расширение добавляет пары, не удаляет старые и не меняет judgments; итоговый размер может превышать новое значение size, если начальные пулы различались. Меняется только draft, не зафиксированные версии.

Отбор лексической системой/тегами создаёт pooling bias. Случайные и межтематические примеры уменьшают его, но не устраняют. Пул фиксируется в версии и может быть расширен для новой версии результатами других систем. Неразмеченные пары вне пула остаются unjudged. Нельзя заявлять исчерпывающий Recall по неполным оценкам или считать неизвестные пары нерелевантными. Здесь никакие метрики не вычисляются.

## Проверка и фиксация

```powershell
.\scripts\docker.ps1 artisan dataset:validate --name=library-stroll-v1
.\scripts\docker.ps1 artisan dataset:freeze --name=library-stroll-v1 --dataset-version=1.0
.\scripts\docker.ps1 artisan dataset:validate --name=library-stroll-v1 --dataset-version=1.0
```

**Параметр `--dataset-version` выбран потому, что `--version` зарезервирован Artisan/Symfony.** Поле в manifest по-прежнему называется `version`.

Валидация разделяет `errors`, `warnings`, `blockers`, `structurally_valid` и `ready_to_freeze`. Отсутствие датировки/языка — предупреждение; неверный SHA, дубликат ID/хеша, подмена пути, некорректная лицензия, изменение снимка/публикации, неверный query/grade — ошибка. Каталог не завершён, запросы не проверены человеком или разметка недостаточна — блокировка готовности. В отчёте есть распределения источников/тем/типов запросов/split и достаточность разметки **каждого** запроса.

Политика в `config/research_dataset.php`: минимум 300 изображений, 80–120 запросов, 20 проверенных объектов и 3 релевантных результата (grade >= 2) на запрос, полное покрытие выбранного пула, минимум 1 независимый разметчик, отсутствие несогласованных оценок. Полноценность источника обязательна. Пороги не следует снижать ради успешного freeze; маленькие тестовые фикстуры используют отдельную явно уменьшенную политику.

`freeze` сначала проверяет готовность, копирует только небольшие артефакты, фиксирует seed/правила/исходный снимок/запросы/оценки/политику/дату, создаёт README и SHA-256 всех файлов. Каталог версии публикуется атомарно; повторная фиксация того же номера запрещена. Для исправления — новый draft и версия 1.1. Публикации платформы остаются редактируемыми; проверка сообщает о расхождении с текущей БД/медиа и ничего не откатывает.

Оригиналы не копируются: отдельно сохраните разрешённую лицензией резервную копию медиа. Для воспроизведения восстановите её, проверьте SHA-256 и версии файлов. Повторное скачивание источника допустимо только при точном совпадении сохранённого SHA; перекодированный/изменённый файл не является тем же снимком. На другом компьютере могут потребоваться восстановленные локальные ID/пути или явное сопоставление по стабильным source ID и хешам; слепой перенос ID между БД недопустим.

Проверка файлов версии в Linux: `sha256sum -c checksums.sha256`. В PowerShell можно сверить `Get-FileHash -Algorithm SHA256` с указанными значениями. `dataset:validate --offline --name=... --dataset-version=1.0` не обращается к БД/demo-manifest, но проверяет локальные медиа. `DatasetVersionManager::readVersion(name,version)` читает и проверяет только зафиксированные артефакты — контракт будущей `ai:evaluate`; её реализация не входит в этот этап.

## Тесты и границы этапа

Автотесты используют защищённый `tests/bootstrap.php`, SQLite `:memory:`, Storage fake, локальные PNG/видео и запрещённые внешние HTTP. Для полной контейнерной проверки применяется контейнер без сети и с отдельным tmpfs storage, без подключения рабочей MySQL. Рабочая база не очищается и миграции удаления данных не запускаются.

Проверяются детерминизм, стратификация, недобор, дубликаты, хеши, авторство/лицензии, идемпотентность/архивирование, CSV/grade 0–3/unjudged, язык/intent/split, привязка оценок к вопросу, отсутствие AI/SQL при чтении версии, неизменность публикаций и запрет перезаписи версий. Результаты реального пилота и полного тестового прогона фиксируются отдельно по окончании проверки.

Остаются человеческие этапы: проверка репрезентативности корпуса, формулировок и эквивалентности запросов, независимая разметка, согласование разногласий и описание pooling bias. Не следует называть автоматически подготовленный черновик готовым gold dataset. Сравнение поиска, AI-обогащение и расчёт Precision/Recall/MRR/nDCG — последующие этапы.
