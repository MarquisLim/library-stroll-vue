# Рабочий запуск векторной индексации

Инструкция обновлена после исправления AI-контура 24 октября 2026 года. Исходный [аудит](ollama-semantic-search-audit.md) сохраняется как исторический снимок найденных проблем.

## Что исправлено

- Qdrant SDK использует `query_points` и `QueryResponse.points`; для похожих артов извлекается настоящий вектор (`with_vectors=True`). Поддерживается `qdrant-client>=1.18,<2`, проверена установленная версия 1.18.0.
- Новая точка получает детерминированный UUID по ID работы; повтор после потерянного ответа обновляет ту же точку. Уже сохранённый point ID также используется повторно. Коллекция Qdrant проверяется/создаётся перед upsert с проверкой размерности.
- API индексации возвращает `embedding_dimension`; Laravel не ставит `indexed`, если ответ не содержит point ID и положительную размерность.
- Исправлена переиндексация после редактирования; общий SHA256 учитывает название, описание, UUID медиа, пользовательские теги, публикацию/видимость, has_ai и версии схемы/prompt.
- Устаревшие задания проверяют ревизию до анализа, после анализа и после индексации; актуальная версия ставится на повторную обработку. Для одной работы задания сериализуются middleware `WithoutOverlapping`.
- Уникальная блокировка отправки задания имеет TTL 900 секунд, блокировка выполнения — 660 секунд: после аварийного завершения worker они не остаются бессрочными.
- В текст для embedding добавлены пользовательские теги и все смысловые поля анализа, включая стили, объекты, настроение и цвета.
- Исправлены отрицательная latency и внешние ключи журнала удаления уже удалённой работы.
- Исправлены передача фильтров в Qdrant и разбиение результатов semantic similar на страницы. Финальная проверка доступа в SQL сохраняется.
- В Ollama отключён thinking (`OLLAMA_THINK=false`), ограничен ответ (`OLLAMA_NUM_PREDICT=768`); одна операция анализа не запускает скрытые повторные генерации JSON.
- Для vision выделено 45 секунд, для text — 100 секунд (`OLLAMA_VISION_TIMEOUT`, `OLLAMA_TEXT_TIMEOUT`). Если vision недоступен или выдаёт невалидный JSON, а название/описание/теги есть, выполняется текстовый анализ. API возвращает `analysis_source=text_fallback`, пустой `vision_model` и `warnings`; Laravel сохраняет эти сведения в журнале AI-операции. Если и text не сработал, задание получает `failed`, фиктивного успеха нет.
- Timeout AI-job — 600 секунд, рекомендуемый `DB_QUEUE_RETRY_AFTER=900`. У поиска отдельный HTTP timeout 15 секунд, у health — 10 секунд, у удаления — 20 секунд на попытку.
- Reconcile восстанавливает зависшие `processing`, старые `pending`, `failed`, `stale`, пропущенные и старые `indexed` записи в пределах заданного лимита.

## 1. Запустить зависимости

Ollama должен отвечать на `http://127.0.0.1:11434` и содержать модели:

```powershell
ollama pull qwen3:8b
ollama pull qwen3-vl:4b
ollama pull qwen3-embedding:0.6b
```

Для Qdrant запустите Docker Desktop и проверьте существующие контейнеры:

```powershell
docker ps -a
```

Если Qdrant ещё не настроен, создайте один контейнер с постоянным volume:

```powershell
docker run -d --name librarystroll-qdrant -p 127.0.0.1:6333:6333 -v librarystroll-qdrant-data:/qdrant/storage qdrant/qdrant
```

Если такой контейнер уже существует, используйте `docker start librarystroll-qdrant`. Не создавайте второй экземпляр на том же порту. Для воспроизводимого окружения зафиксируйте проверенный в вашем развёртывании тег образа. Контейнерный сервер не подменяется Qdrant в памяти при обычном запуске приложения.

Python API запускается из каталога `ai-service`:

```powershell
Set-Location B:\projects\library-stroll-vue\ai-service
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

Настройки находятся в `ai-service/.env`. Пример новых параметров:

```dotenv
OLLAMA_THINK=false
OLLAMA_NUM_PREDICT=768
OLLAMA_VISION_TIMEOUT=45
OLLAMA_TEXT_TIMEOUT=100
QDRANT_URL=http://127.0.0.1:6333
QDRANT_COLLECTION=librarystroll_artworks
```

Пустая новая коллекция создаётся автоматически по размерности настоящего embedding. Существующая коллекция несовместимой размерности не удаляется: выберите новое имя и выполните переиндексацию. При замене embedding-модели требуется полная переиндексация даже при той же размерности.

## 2. Включить Laravel и worker

В корневом `.env`:

```dotenv
AI_SERVICE_ENABLED=true
AI_SERVICE_URL=http://127.0.0.1:8001
QUEUE_CONNECTION=redis
REDIS_QUEUE_RETRY_AFTER=900
```

При использовании API key он должен совпадать в обоих `.env`. После изменения конфигурации:

```powershell
Set-Location B:\projects\library-stroll-vue
php artisan migrate
php artisan config:clear
php artisan ai:health
php artisan queue:work redis --queue=ai --timeout=600 --tries=3
```

`ai:health` теперь возвращает ошибку, если AI выключен. Проверка Ollama учитывает наличие всех трёх настроенных моделей, Qdrant — наличие целевой коллекции. Это проверка доступности; скорость генерации и качество моделей измеряются отдельно. Код `indexed` в MySQL сам по себе не является проверкой наличия точки после внешней потери Qdrant storage.

На проверяемом компьютере отдельный реальный text-анализ после исправления завершился примерно за 62 секунды. Vision на полном тестовом изображении не ответил за прежний timeout 180 секунд; поэтому успешный результат vision не заявляется и предусмотрен явный текстовый fallback. Результат fallback описывает текстовые данные, а не подтверждённое содержимое изображения. Для импорта музея это позволяет использовать его фактическое название и теги при построении embedding.

Используйте PHP 8.2. `composer dev` теперь запускает отдельные Redis workers `default` и `ai`, но не запускает Ollama, Qdrant или Python API. Для медиа используется очередь `default`. На Windows нет `pcntl`, поэтому важно иметь ограниченные сетевые таймауты, а не полагаться только на timeout worker. Настройка и проверка Redis описаны в [redis-setup.md](redis-setup.md).

## 3. Импортировать арты и заполнить векторы

```powershell
php artisan artworks:import --source=met --query=landscape --limit=20 --publish --index
```

Команда сохраняет работу и музейные теги, создаёт `artwork_ai_metadata` со статусом `pending` и ставит задание в очередь `ai`. **Вектор появляется после успешной обработки worker**, а не в момент добавления задания. Анализ изображения, embedding и upsert выполняются настоящими моделями; фиктивные векторы не создаются.

`--index` требует `--publish` и включённый AI. Без них команда остановится до создания работ. `--dry-run` не вызывает модели и не ставит задания даже с `--index`.

Для уже существующего опубликованного арта:

```powershell
php artisan ai:index-artwork 42
```

Для всего опубликованного каталога:

```powershell
php artisan ai:reindex-all
```

Команда запросит подтверждение и поставит задания в очередь; она не ожидает завершения моделей. Это также способ заполнить векторы для ранее импортированных работ: повторный `artworks:import` пропускает уже существующие объекты.

`php artisan db:seed --class=ArtworkSeeder` использует новый импорт. Если AI включён, обёртка передаёт `--index` автоматически; если выключен — создаёт только опубликованные работы. Обычный `db:seed` и `data:setup` заполняют справочники и не создают арты, поэтому сами по себе не создают и векторы.

## 4. Следить за результатом

```powershell
php artisan ai:status
php artisan ai:status --errors=10
php artisan queue:failed
```

`pending` — задание ожидает worker; `processing` — выполняется; `indexed` — ответ индексации сохранён; `failed` — в выводе будет причина; `stale` — требуется повторная обработка. `ai:status` читает только MySQL и не выполняет inference.

Проверка векторного результата: выполнить смысловой запрос на `/search`, открыть похожие работы, проверить `indexed`, ненулевую размерность и ID точки. Если AI недоступен, публичный поиск может перейти на SQL fallback — наличие обычной выдачи не доказывает, что векторы работают.

## 5. Что проверялось при исправлении

PHP-проверки покрывают импорт `--index`, очередь, смену тегов, устаревшую ревизию, исполнение job, размерность, ошибки индекса, журнал удаления и восстановление зависших задач. Python-тесты используют настоящий Qdrant SDK с базой в памяти: запись, поиск, similar, фильтры, повторы и удаление.

Отдельный opt-in тест вызывает реальные Ollama-модели через Python API и использует изолированный Qdrant в памяти:

```powershell
Set-Location B:\projects\library-stroll-vue\ai-service
$env:RUN_AI_SMOKE = '1'
.\.venv\Scripts\python.exe -m pytest tests/test_live_pipeline.py -q -s -p no:cacheprovider
Remove-Item Env:RUN_AI_SMOKE
```

Он не записывает точки в рабочий Qdrant и не изменяет MySQL. В обычном pytest этот тест пропускается, чтобы не запускать тяжёлые модели без явного выбора. Docker/Qdrant и постоянный worker необходимо запустить отдельно; исправление исходников не означает, что эти процессы уже запущены на компьютере.

Финальная проверка в этом окружении: PHP — 124 теста, 334 assertions, 7 пропущены по настройкам Jetstream; Python — 29 passed, 1 opt-in test skipped. Отдельно opt-in тест прошёл за 64,54 секунды: запрос с изображением был обработан как `text_fallback`, реальные embeddings имели размерность 1024, русский поиск выбрал ожидаемый текст, similar/идемпотентный повтор/удаление работали на настоящем Qdrant SDK в памяти. Успех постоянного Docker-сервера этим тестом не проверялся.
