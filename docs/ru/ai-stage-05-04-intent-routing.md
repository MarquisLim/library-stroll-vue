# Library Stroll · 5.4-1A. Маршрутизация намерений

28 ноября 2026 г. · ветка `docker` · исходный коммит `9bb2d03e1108d9bee963230a6fa4fbf56123e493`.

В 75 парных контролях новый маршрутизатор сократил ошибочные запуски поиска с **44 до 2** и направил в поиск **все 14** предназначенных для него запросов. Accuracy составила **86,7 %**, macro F1 — **0,855**. Все 8 запросов неподдерживаемых медиа завершились без поиска. Для 14 общих поисковых пар совпали исходная фраза, кандидаты, ранги и источники RAG. Режим доступен по флагу для контролируемого использования. Значение по умолчанию оставлено `false` из-за двух ложных запусков на независимых неоднозначных формулировках и хвоста задержки первого поискового хода.

## Аудит и область действия

| Точка | Поведение до 5.4-1A | Поведение с флагом |

| `AssistantTurnController`, последующие ходы | При включённом контексте `AssistantTurnContext` собирал предыдущие запросы и подтверждённые ссылки, а `AssistantFollowupResolver` выбирал новый поиск, прежние источники или уточнение. | `AssistantSearchController`, `/assistant/search` | Целевой API поиска изображений. При `AI_ASSISTANT_LLM_ENABLED` возможна ограниченная нормализация запроса или уточнение через `AssistantQueryNormalizer`. | Тот же контракт `status` и `results`, с существующим `clarification_code` при уточнении. |

Маршрутизация применяется к `POST /assistant/conversations/{id}/turns`. При выключенном флаге этот маршрут пользуется прежней диспетчеризацией. Прямые API сохраняют поведение и используются как интерфейсы поиска, в том числе при выключенной истории. Применяются прежние проверки владения диалогом и CSRF и общая квота 10 запросов в минуту.

## Реализация

`AssistantIntentRouter` поручает смысловую классификацию `qwen3:8b` через внутренний `POST /api/v1/assistant/classify-intent`. FastAPI и Laravel проверяют единственное поле `intent` по закрытому списку из десяти значений. FastAPI принимает только `query`, экранирует управляющие разделители модели и ограничивает генерацию 48 токенами. Никакие аргументы вызовов, URL, тексты ответов или условия поиска из классификатора не принимаются. Действие выбирает Laravel. Поисковая фраза передаётся без переписывания и без вызова нормализатора или resolver для самостоятельного поискового хода.

Локальные правила закрывают чистое приветствие, запрос с однозначным заголовочным типом неподдерживаемого медиа, несколько пустых команд и явные инструкции о смене системных правил. Поиск после приветствия остаётся поиском. Упоминание видеокамеры как объекта изображения не считается запросом видео. При отказе классификатора безопасный fallback разрешает явные команды поиска с указанным изображением и объектом либо коротким однозначным визуальным предметом. Остальные случаи направляются на уточнение. Бюджет входа и таймаут могут привести к такой же деградации. Доступность дальнейшего Dense и composer зависит от состояния их сервисов.

`AssistantTurn` хранит информационный ответ как зашифрованный `reply_code`, например `ru.greeting`. `AssistantConversationHistory` допускает только известные коды и пустые ссылки у статуса `informational`. Текст берётся из фиксированных русских и английских шаблонов при свежем ответе, чтении и экспорте. Кириллический запрос получает русский шаблон, остальные запросы — английский. Прежние записи допускают `NULL`. Vue показывает текст без карточек и не подменяет его состоянием пустой поисковой выдачи. Запрос на структурирование получает сообщение о фактической доступности функций. Коллекции, теги и файлы этот маршрут не меняет.

`AssistantSearchDiagnostics` записывает намерение, способ (`llm`, `rule`, `fallback`), действие, причину деградации классификации или контекста, время и счётчики вызовов. Клиентский блок «Как выполнен поиск» показывает эти поля, токены и признаки запуска retrieval и composer. Пропущенный этап имеет `null` в `stages` и `false` в `execution`. Пройденный поиск с нулём результатов имеет заполненный этап и `true`. Нулевой счётчик вызовов означает пропуск, `null` означает, что попытка была, но число обращений к Ollama неизвестно. Расширенный экспорт сохраняет эти поля в диагностике хода. В него не передаются системные инструкции, сырой ответ модели и данные аутентификации.

## Контрольные данные и протокол

Разметка из 75 запросов зафиксирована перед запуском. В неё вошли 25 заданных и 50 независимых формулировок, 35 первых и 40 последующих ходов. SHA-256 файла разметки — `14ed58cf11eac5866c8257c4e97069932c7a4eb4b9c16d8c311e525af632d7f5`. Ожидаемый класс определяется смыслом запроса, в том числе когда ссылка на прежнюю работу в первом ходе разрешиться не может. Новый поиск ожидается только для `search_media`. Независимые случаи не использовались для настройки по результатам замера. Вручную собранная выборка покрывает десять классов. Доли ошибок относятся к её составу. [Разметка](../../scripts/research/assistant-intent-cases.json) · [Фиксация разметки](../../storage/app/ai-stage-05-04/5.4-1a/dataset-freeze.json).

Оба варианта вызваны в одном локальном стенде через валидацию и `AssistantTurnController`. Использовались `qwen3:8b` и `qwen3-embedding:0.6b`. Для каждого последующего хода заранее добавлялся один и тот же предыдущий поисковый ход с тремя действующими ссылками на работы #284, #286 и #76. История хранилась во временных таблицах одного подключения MySQL. Контейнер FastAPI был отдельным, с доступом к существующей коллекции. После пробного прогрева каждый запрос выполнен один раз на стратегию, порядок A/B и B/A чередовался. Полное серверное время включает валидацию, поиск или информационный ответ, повторную проверку источников, сохранение хода и JSON. Развёртывание, сетевой обмен с браузером и отрисовка в замер не входят. p50 и p95 рассчитаны с линейной интерполяцией.

У A отсутствует классификация в десять классов. Для сопоставимой матрицы `new_search` учитывается как `search_media`, `use_previous` как `followup`, `clarify` как `clarify`. Метрики A характеризуют прежнее действие по этому отображению. Precision при нуле предсказаний принята равной нулю. Macro F1 в срезе усредняется по классам, представленным в его эталоне.

## Решение и воспроизведение

Преимущество по ложным запускам, сохранённые поиски и результаты RU/EN обосновывают контролируемый запуск по `AI_ASSISTANT_INTENT_ROUTING_ENABLED=true` в Laravel и FastAPI. Для развёртывания сначала применяется миграция nullable `assistant_turns.reply_code`. Для обычного чтения уже записанного информационного ответа включать маршрутизатор не требуется. Рабочее окружение в ходе этапа не переключалось. Для включения по умолчанию остаются неопределённость коротких запросов и хвост задержки первого поиска. В итоговую выборку исправления после оценки не вносились.

Полный набор Laravel завершился успешно, 599 тестов и 8 пропусков. В FastAPI прошли 200 тестов при двух пропусках. Прошли 25 JavaScript-тестов и сборка Vite. Проверки покрывают transport failure, timeout, невалидный JSON, неизвестный класс и лишние поля, попытки сменить роль модели, ложное `search_media` для запроса видео, отсутствие истории и отзыв доступа к прежней работе. Проверено восстановление зашифрованного информационного ответа при выключенном маршрутизаторе, чтение старых записей, обычный и расширенный экспорты, совместимость прямых API и ограничение области прежних источников. [Laravel](../../storage/app/ai-stage-05-04/5.4-1a/laravel-tests.txt).

Скрипт сводки проверяет соответствие запросов, порядка пар и поисковых результатов и формирует метрики.
