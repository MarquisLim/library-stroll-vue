# Этап 5.4-1D-3A. Подготовка человеческой оценки поиска

Подготовлены **2 305 уникальных пар «запрос — изображение»** и **119 отдельных проверок условий**. Перед выбором итоговой конфигурации их оценивает владелец проекта. Разметка и выбор конфигурации в этом этапе не проводились.

## Исходные данные

Работа начата в ветке `docker` с коммита `f56b8f115462304c13c3f9791c5d2b195cf0be30`. Для очереди использованы сохранённые ранги шести стратегий 5.4-1D-1 и базовых, Oracle и end-to-end вариантов 5.4-1D-2. Регрессия 5.4-1C учитывается по тем же формулировкам и критериям, которые были перенесены в 5.4-1D-1 и 5.4-1D-2. Исторический корпус и результаты человеческой оценки 4.8 остаются отдельными. Расчёты предварительной оценки ColBERT и Constraints сохраняют прежние команды и файлы. Для новой очереди есть единый импорт обоих исследований. [5.4-1C](ai-stage-05-04-hybrid-search.md) · [5.4-1D-1](ai-stage-05-04-colbert-reranking.md) · [5.4-1D-2](ai-stage-05-04-constraint-reranking.md) · [4.8](ai-stage-04-08-evaluation.md).

Пара определяется точным совпадением четырёх полей. Это исходный запрос, критерий, ID работы и SHA-256 подготовленного JPEG. Переводы, нормализация пунктуации и сходство формулировок при объединении не используются. Одна запись может участвовать в нескольких исследованиях. Для неё сохраняются источник и принадлежность к срезам в закрытом для интерфейса `provenance.json`. Изменение любого из четырёх полей создаёт самостоятельную пару. При отсутствии точной версии изображения в исходной очереди допустима только однозначная ссылка на замороженную копию из другого среза.

| Срез без повторного подсчёта пары | P1 · топ-5 | P2 · дополнение до топ-10 | P3 · дополнение до топ-20 | P4 · за пределами топ-20 | Всего |
|---|---:|---:|---:|---:|---:|
| Независимые запросы | 672 | 524 | 540 | 58 | 1 794 |
| Только регрессионные запросы | 192 | 137 | 153 | 29 | 511 |
| **Единая очередь** | **864** | **661** | **693** | **87** | **2 305** |

В источниках было 1 120 независимых и 500 регрессионных записей 5.4-1D-1, ещё 674 независимые и 11 дополнительных регрессионных записей 5.4-1D-2. В этих уже дедуплицированных очередях **0** повторяющихся строк по четырём полям. Если разметить материалы отдельно для каждого сохранённого среза, одна и та же работа с тем же запросом понадобится повторно **1 631 раз**. В объединённой очереди каждая такая пара оценивается один раз. В частности, 1 120 пар одновременно относятся к независимому срезу ColBERT и его регрессии в Constraints. Пул 5.4-1C из 511 пар используется в обоих регрессионных расчётах.

Приоритет определяется лучшей сохранённой позицией по всем сопоставимым стратегиям. P4 содержит подготовленные контрольные пары вне объединённого топ-20. Внутри приоритета пары с одним точным запросом и критерием идут подряд. Порядок групп и изображений определяется хешами и не зависит от рангов и предварительных оценок. Для всех вариантов проверено покрытие топ-20. Замороженные списки и их хеши доступны в манифесте. ## Инструкция для владельца

Запуск из корня репозитория в PowerShell.

```powershell
pwsh -NoProfile -File scripts/research/relevance-review/start-human-review.ps1
```

Откройте [локальную страницу оценки](http://127.0.0.1:48095/). Введите короткий идентификатор латиницей, например `owner-01`. Для восстановления прогресса после закрытия браузера или перезапуска сервера используйте тот же идентификатор. Страница хранит позицию и оценки на диске.

1. В «Релевантности» пройдите P1. Оценивайте изображение по показанному запросу и критерию. Кнопки приоритетов показывают остаток и открывают первую неоценённую пару выбранного приоритета. Продолжите P2, P3 и P4 по мере доступного времени. Для одной формулировки переходите между соседними изображениями с сохранением текущего критерия.
2. Поставьте **2**, если совпадают основные элементы запроса. Поставьте **1**, если видна только существенная часть. Поставьте **0**, если изображение нерелевантно. Выберите **«Не уверен»**, когда деталей изображения недостаточно для решения.
3. В «Отдельных условиях» оценивайте только показанное утверждение об изображении. Есть три ответа — «Условие выполнено», «Условие не выполнено» и «Невозможно определить». Отдельная очередь содержит все 119 контрольных заданий 5.4-1D-2, включая условие о красных цветах на работе №467. Порядок заданий и формулировки скрывают прежний вывод алгоритма. [Очередь условий](../../storage/app/ai-stage-05-04/5.4-1d-3a/conditions-queue.json).
4. Используйте клавиши **2**, **1**, **0**, **?** или **N** для ответа, **←** и **→** для перехода, **Z** для увеличения. В увеличенном просмотре **+** и **−** меняют масштаб, **Esc** закрывает окно. В очереди условий доступны **2**, **0** и **?**. Переход назад позволяет исправить ответ.
5. Выгрузите «Экспорт JSON» отдельно из каждой очереди. Экспорт доступен при частичном прохождении. Сохраните исходные файлы JSON для расчёта в 5.4-1D-3C.

Веб-сервер привязан к `127.0.0.1`. Оценщик получает только запрос, критерий, изображение и сведения о прогрессе. Ранги, сравниваемые стратегии, автоматические оценки, Query Understanding и решения Constraints не выдаются. Желательно проходить слепую оценку без просмотра служебного манифеста и прежних результатов.

Рабочие ответы сохраняются в `storage/app/ai-stage-05-04/5.4-1d-3a/human-review/relevance/` и `human-review/conditions/` в файлах `reviewer-<идентификатор>.json`. Пробный запуск с `-Test` использует порт 48096, отдельный каталог `synthetic-review/` и источник `synthetic_test`. Импорт отклоняет такие выгрузки.

## Последующий расчёт

Укажите фактический путь к сохранённому экспорту. Для второй очереди применяется та же команда с её JSON.

```powershell
node scripts/research/relevance-review/human-metrics.mjs ".\human-review-relevance-owner-01.json"
node scripts/research/relevance-review/human-metrics.mjs ".\human-review-conditions-owner-01.json"
```

Результаты создаются отдельно в `storage/app/ai-stage-05-04/5.4-1d-3a/human-metrics/`. Имя включает вид очереди, идентификатор проверяющего и часть SHA-256 экспорта. Импорт проверяет источник `manual_ui`, версию схемы, SHA-256 очереди, допустимость пары и отсутствие повторной оценки в файле. Сопоставление с каждым из пяти срезов проверяет SHA-256 исходных рангов и замороженной очереди. Прежние предварительные результаты не переписываются. [Импорт и расчёт](../../scripts/research/relevance-review/human-metrics.mjs).

Для релевантности предусмотрены nDCG@5/10, Hit@1/5, MRR@5, Recall@5/10/20/50 по известным полным совпадениям, покрытие и число подтверждённых полных совпадений в топ-5. Для каждого показателя приводится число учтённых запросов. Числовые оценки, ответы «Не уверен» и пропущенные позиции учитываются раздельно. Показатель глубины рассчитывается для запроса и стратегии только при полном числовом покрытии соответствующего префикса. Пустой знаменатель даёт `null`. После разметки P1 Recall@20/50 останутся пустыми там, где соответствующие позиции ещё не оценены. Даже после полного прохождения подготовленной очереди Recall@50 может остаться недоступным из-за ограниченной глубины пула. Для сравнений используются общие запросы с доступной оценкой в обоих вариантах и парный бутстрэп из 10 000 выборок. Срезы независимых запросов, регрессий, RU и EN выгружаются раздельно.

Для условий рассчитывается согласие независимых человеческих ответов с сохранёнными выводами Oracle и end-to-end. В матрице три состояния, пропущенные задания учитываются отдельно. Оценки релевантности и условий сохраняются и рассчитываются отдельно.

## Проверки и целостность

Все 444 уникальных JPEG декодированы. HTTP выдаёт ровно те байты, SHA-256 которых указан в замороженных очередях. Максимальная длинная сторона — 1 000 пикселей, минимальная короткая — 160. В браузере проверены увеличение, клавиатура, P2, переход к отдельным условиям и восстановление выбранной очереди после перезагрузки. Автоматически проверены перезапуск сервера, редактирование, экспорт, неверный хеш, посторонняя пара, дубликат, изоляция тестовых оценок и запрет выдачи служебных файлов. Прошли **34 JavaScript-теста**. В рабочем режиме подтверждено отсутствие сохранённых человеческих оценок. [Тесты](../../storage/app/ai-stage-05-04/5.4-1d-3a/review-tests.txt) · [Проверка браузера](../../storage/app/ai-stage-05-04/5.4-1d-3a/ui-smoke.json) · [Проверка изображений](../../storage/app/ai-stage-05-04/5.4-1d-3a/image-decode.json).

Все 511 актуальных Vision-записей сохранились по SHA-256 `5ef8d5d93e8dfdd1ed660b81ed9c49bf5e97642ae2ab4afc100075713613e444`. SHA-256 его исходных 108 965 байтов совпал с начальным снимком. Новые поисковые прогоны, переиндексация и Vision-анализ не выполнялись.
