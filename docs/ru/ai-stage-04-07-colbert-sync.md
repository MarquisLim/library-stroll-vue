# 4.7A-1 — Динамическое обновление ColBERT

Исследовательский прототип `scripts/research/colbert_http.py` обновляет токеновые представления отдельных работ в памяти. Он загружает сохранённые тексты 100 работ из 4.5A и один экземпляр `jinaai/jina-colbert-v2`. Использованы те же веса на ревизии `a9dc5cd7293d4c71dbbba04829923ba4d0e4f6ea`, код модели на ревизии `bd55a5ec8e6c0fb1d6c26efb4b6a4a74ce8a88d3` и прежний MaxSim. Прототип предназначен для локального некоммерческого исследования. [Модель и лицензия CC BY-NC 4.0](https://huggingface.co/jinaai/jina-colbert-v2).

## Запуск и API

В окружении Python из 4.5A, где доступен пакет схем `ai-service/app`, запустите из корня репозитория:

```powershell
$env:PYTHONPATH = (Resolve-Path 'ai-service').Path
python scripts/research/colbert_http.py storage/app/ai-stage-04-05 --model storage/app/ai-stage-04-05/model --device cuda --port 18052 --dynamic-documents
```

Флаг `--dynamic-documents` открывает маршруты документов на `127.0.0.1` в одном процессе Uvicorn. Маршруты проверяют адрес клиента и заголовок `Host`. Аргумент `--container` несовместим с этим флагом. При обычном запуске доступны прежние маршруты готовности и reranking.

| Запрос | Поведение |
| --- | --- |
| `GET /api/v1/documents/{artwork_id}` | Возвращает наличие, `content_hash`, `version` и число токенов работы. |
| `PUT /api/v1/documents/{artwork_id}` | Принимает `searchable_text`, `expected_previous_hash` и `expected_previous_version` в JSON. Оба ожидаемых значения должны быть `null` для первой записи ID. При обновлении берите их из GET или последней успешной записи. |
| `DELETE /api/v1/documents/{artwork_id}` | Принимает `expected_previous_hash` и `expected_previous_version` в параметрах запроса. Удаляет представление действующей версии. |

Сервис вычисляет `content_hash` как SHA-256 точного текста UTF-8. Laravel отдельно вычисляет хеш ревизии публикации. Каждое изменение получает новую `version`. Запрос, который изменил бы состояние при несовпадающей версии или хеше, получает HTTP 409 даже после возврата прежнего текста. Повторная отправка текущего текста возвращает `unchanged` без кодирования. Повторное удаление отсутствующего ID возвращает `absent`. Маркер удалённого ID хранит версию в памяти. Чтобы создать документ заново, передайте `null` как ожидаемый хеш и версию маркера. GET возвращает их и для удалённого ID. Запрос reranking с неизвестным ID получает HTTP 422.

Обновление сверяет ревизию и кодирует один документ под той же блокировкой, которую использует reranking. Запрос поиска видит либо прежнее, либо новое представление целиком. При ошибке кодирования прежняя версия остаётся доступна. Пока модель кодирует документ, параллельный reranking ждёт освобождения блокировки. `GET /ready` в исследовательском режиме показывает текущий размер корпуса и суммарное число закодированных документов с момента запуска.

Без `--state-dir` изменения, включая удалённые ID, живут до перезапуска процесса. Новый процесс загружает исходный корпус и выдаёт новые версии документов. Laravel Jobs не подключены к этим маршрутам.

## 4.7A-2 — Восстановление после перезапуска

В подготовленном исследовательском Python-окружении под Linux или WSL запустите сервис из корня репозитория с прежними локальными весами и отдельным каталогом состояния.

```bash
PYTHONPATH=ai-service python scripts/research/colbert_http.py storage/app/ai-stage-04-05 \
  --model storage/app/ai-stage-04-05/model --device cuda --port 18052 \
  --dynamic-documents --state-dir storage/app/ai-stage-04-07/local-state
```

Для локального запуска `--state-dir` используется вместе с `--dynamic-documents`. Повторный запуск с тем же каталогом восстанавливает сохранённое состояние. Блокировка `state.lock` занята на всё время работы процесса. Второй процесс с тем же каталогом завершает запуск с ошибкой.

`state.json` содержит снимок формата `1` и его SHA-256. В снимке сохранены идентификатор модели, ревизии весов и кода, SHA-256 весов и хеш корпуса по упорядоченным ID и хешам исходных текстов. Для каждого документа сохраняются ID, `content_hash` и `version`. Поле `searchable_text` содержит открытый текст добавленных и изменённых документов. Для исходного текста оно равно `null`. Удаление представлено записью с `content_hash=null`, `searchable_text=null` и действующей версией маркера. Тензоры и веса модели в снимок не записываются.

Сервис под существующей блокировкой записывает новый снимок во временный файл в том же каталоге, сбрасывает его на диск через `fsync` и атомарно заменяет `state.json`. Он меняет версию и представление в памяти после успешной замены. При ошибке записи PUT или DELETE возвращает HTTP 503, а предыдущая версия остаётся доступной. Повтор текущего текста и повтор удаления отсутствующего ID обходятся без записи.

При запуске сервис проверяет снимок и его совместимость с моделью и корпусом. После обычного кодирования исходных 100 документов он кодирует только документы с сохранённым новым текстом, убирает удалённые ID и восстанавливает все версии. Возврат исходного текста сохраняет новую версию и при следующем запуске использует представление из исходного батча. Повреждённый или несовместимый снимок останавливает запуск, файл сохраняется для проверки. Режим рассчитан на один процесс и локальную файловую систему. Проверено восстановление после перезапуска процесса.

## 4.7A-3 — Внутреннее взаимодействие Laravel и ColBERT

Дополнительный файл `compose.colbert-research.yaml` подключается к сохранённому проекту `library-stroll-44-dataset`. Он добавляет отдельную сеть с `internal: true` для `app` и `colbert`. Laravel обращается к `http://colbert:8001`. Порт ColBERT внутри сети доступен на контейнерном интерфейсе. На хосте порт не публикуется.

ColBERT запускается с `--internal-dynamic-documents`, и ему нужны `--state-dir` и файл непустого ключа `AI_COLBERT_SYNC_API_KEY_FILE`. Для всех методов маршрута `/api/v1/documents/{id}` требуется заголовок `X-ColBERT-Sync-Key`, сравниваемый через `hmac.compare_digest`. Пропущенный или неверный ключ даёт HTTP 401. `/ready` используется для проверки здоровья внутри контейнера. Локальный `--dynamic-documents` и прежний `--container` сохраняют свои режимы работы. Прототип использует HTTP внутри выделенной сети для некоммерческого исследования. [Лицензия CC BY-NC 4.0](https://huggingface.co/jinaai/jina-colbert-v2).

Веса и Python-окружение 4.5A монтируются только для чтения. Сервис работает в офлайн-режиме. Том `colbert-state-47a-3` монтируется в домашний каталог непривилегированного пользователя образа. Состояние и блокировка хранятся в `/home/service/colbert-state`. Перезапуск ColBERT сохраняет версии и маркеры удалений.

### Запуск в проекте 4.4C

Из корня репозитория создайте отдельный ключ в каталоге, исключённом из Git. Команда сохраняет существующий ключ, если он уже есть.

```powershell
$secret = Join-Path (Get-Location).Path 'storage/app/ai-stage-04-07/colbert-sync.key'
if (-not (Test-Path -LiteralPath $secret)) {
    $null = New-Item -ItemType Directory -Path (Split-Path -Parent $secret) -Force
    $key = [Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(32)).ToLowerInvariant()
    [IO.File]::WriteAllText($secret, $key + [Environment]::NewLine)
    Remove-Variable key
}
$dataset = 'storage/app/ai-stage-04-04'
$researchArgs = @('-p', 'library-stroll-44-dataset', '--env-file', "$dataset/isolated.env",
    '-f', 'compose.yaml', '-f', "$dataset/compose.dataset.yaml", '-f', 'compose.colbert-research.yaml')
docker compose @researchArgs up -d --no-deps --no-build --pull never app colbert
docker compose @researchArgs ps app colbert
```

Оба контейнера получают ключ через Compose secret в `/run/secrets/colbert_sync_key`. Конфигурация основного Compose-проекта подключается как прежде. Для ручных вызовов доступен клиент `App\Services\AiService\ColbertDocumentClient`.

| Настройка Laravel | Назначение |
| --- | --- |
| `AI_COLBERT_SYNC_ENABLED` | По умолчанию `false`. Исследовательский Compose включает клиент только в `app`. |
| `AI_COLBERT_SYNC_URL` | Адрес операций с документами. В исследовательской сети это `http://colbert:8001`. |
| `AI_COLBERT_SYNC_API_KEY` | Ключ для явной настройки клиента через переменную окружения. В Compose клиент читает файл `AI_COLBERT_SYNC_API_KEY_FILE`. |
| `AI_COLBERT_SYNC_CONNECT_TIMEOUT` | Таймаут соединения в секундах, по умолчанию 0,25 с и максимум 2 с. |
| `AI_COLBERT_SYNC_TIMEOUT` | Таймаут запроса в секундах, по умолчанию 2 с и максимум 10 с. |

Клиент выполняет один HTTP-запрос без редиректов. Методы `get()`, `upsert()` и `delete()` возвращают `content_hash` и `version` ColBERT. Для записи передавайте хеш текста и версию из ответа ColBERT. Хеш ревизии Artwork вычисляется отдельно. При ошибке `ColbertDocumentException` сохраняет код HTTP 401/403, 409 или 503. Сетевая ошибка имеет код `0`. Сообщение исключения формируется локально и не содержит тела ответа или ключа. После сетевого сбоя GET позволяет сверить актуальную версию перед следующей попыткой изменения.

## 4.7A-4-1 — Автоматическая синхронизация после Dense-индексации

После успешного upsert в Qdrant и сохранения актуального статуса `indexed` Laravel ставит `SyncArtworkColbertJob` в существующую очередь AI после commit. Задача получает точный `searchable_text` Dense-индексации, ID работы, хеш ревизии, ID метаданных и номер Dense-попытки. Текст в payload очереди шифруется средствами Laravel. Если постановка не удалась, журнал содержит ID работы, хеш и ID запуска Dense. Статус успешной Dense-индексации сохраняется.

Задача берёт общую блокировку `ArtworkAiJobLock` и сверяет текущую допустимость работы, хеш ревизии, статус `indexed` и номер Dense-попытки. Номер отличает два анализа одной и той же ревизии. После GET она пропускает уже сохранённый SHA-256 текста. Перед PUT она снова проверяет Laravel и передаёт полученные от ColBERT хеш и версию. Ответ PUT сверяется с хешем исходного текста.

При HTTP 409 задача перечитывает Laravel и ColBERT. Если ожидаемый текст уже записан, она завершается. Повторный PUT с новой версией допускается один раз, пока Laravel подтверждает ту же Dense-попытку, а ColBERT всё ещё хранит тот же предыдущий текст. Если за это время появился другой текст или маркер удаления, задача завершает конфликт без перезаписи. После известного конфликта сбой повторной проверки тоже завершает задачу с диагностикой, чтобы следующий запуск не потерял исходное условие записи.

Сетевая ошибка или HTTP 503 вне разрешения конфликта запускает повтор на уровне очереди. Без ожидания общей блокировки после первых двух исключений задержки составляют 15 и 60 секунд, третье завершает задачу ошибкой. Занятая блокировка переносит запуск на 30 секунд в пределах общего лимита резервирований. При окончательном отказе журнал фиксирует ID, ревизию, Dense-попытку и код ошибки без текста и ключа.

`AI_COLBERT_AUTO_SYNC_ENABLED` по умолчанию выключен. Флаг отвечает за автоматические задания, `AI_COLBERT_SYNC_ENABLED` — за HTTP-клиент. Для автоматического режима нужны оба. Исследовательский Compose даёт `worker-ai` доступ к `colbert-sync`, URL и существующему Compose secret. Для целевого прогона с уже запущенными изолированными зависимостями 4.4C используйте аргументы `$researchArgs` из предыдущего раздела.

```powershell
$env:AI_COLBERT_AUTO_SYNC_ENABLED = 'true'
docker compose @researchArgs up -d --no-deps --no-build --pull never colbert worker-ai
Remove-Item Env:AI_COLBERT_AUTO_SYNC_ENABLED
```

Чтобы отключить режим, пересоздайте `worker-ai` с теми же аргументами после удаления переменной. Настройка reranking управляется отдельно.

Проверка Laravel и удалённый PUT выполняются последовательно. Изменение публикации во время HTTP-запроса ещё может оставить устаревшее представление в ColBERT. Удаление описано ниже. Периодическая сверка, включая восстановление пропущенной постановки, относится к отдельному этапу.

В одноразовом контейнере без сети прошли 137 целевых тестов PHP (700 проверок), включая 25 новых сценариев. На SQLite и HTTP-моках проверены commit, rollback, сбой постановки, неизменённый текст, устаревшая Dense-попытка, конфликт и три попытки очереди при HTTP 503 и сетевом отказе. ## 4.7A-4-2 — Автоматическое удаление документов ColBERT

Существующий путь `ArtworkIndexVisibility` создаёт задачу удаления из Qdrant при физическом удалении работы, снятии с публикации, переводе в приватный режим, блокировке работы или автора и при отключении AI-индексации. После успешного Dense-удаления и commit записи об операции `DeleteArtworkIndexJob` ставит отдельный `DeleteArtworkColbertJob` в очередь `ai`. В payload передаются ID работы и `request_id` Dense-операции. Оба существующих флага синхронизации должны быть включены. Сбой постановки логируется с этими ID, успешная запись об удалении из Qdrant сохраняется.

Удаление и обновление ColBERT используют общую блокировку `ArtworkAiJobLock`. Задача проверяет актуальную доступность через `canIndex()` перед GET и непосредственно перед DELETE. Если работа снова доступна или документ уже отсутствует, задача завершается. Для DELETE используются хеш текста и версия из GET. Ответ проверяется на отсутствие документа, при фактическом удалении требуется новая версия маркера.

При HTTP 409 задача перечитывает состояние. Если работа снова доступна или документа уже нет, дополнительный DELETE не нужен. Если документ остался или перечитать состояние не удалось, конфликт фиксируется без новой попытки удаления. Сетевой отказ или HTTP 503 вне этой проверки повторяется через очередь по той же политике, что и обновление. Без ожидания блокировки задержки после первых двух исключений составляют 15 и 60 секунд, третье завершает задачу. Журнал окончательного отказа содержит ID работы, `request_id`, тип ошибки, HTTP-статус при наличии и число резервирований. Текст документа, ключ и тело ответа в журнал не передаются.

Между последней проверкой в Laravel и выполнением DELETE на стороне ColBERT остаётся окно для изменения публикации. Блокировка сериализует AI-задачи для одной работы. HTTP-версия защищает документ от удаления по устаревшему GET. Сверка двух индексов и восстановление пропущенных операций отложены до 4.7A-4-3.

Прошли 159 целевых тестов PHP (832 проверки), включая 22 новых сценария. В контейнере без сети на SQLite и HTTP-моках проверены все пути ограничения видимости, commit и rollback, повторная публикация до запуска задачи и во время GET, идемпотентность удаления, конфликт версии, сбой постановки, повторы при сетевой ошибке и HTTP 503, общая блокировка с обновлением и регрессии Hybrid Search. Сохранённый корпус 4.4C в проверке не использовался.
