# 5.4-1A0. Диагностика поиска и экспорт диалогов

## Что записывает ассистент

Переключатель «Диагностика поиска» включает запись для следующих запросов и показывает существующие снимки при открытии сохранённого диалога. Карточка показывает Dense Score с тремя знаками после запятой, Dense Rank, Lexical Rank, Hybrid Rank и RRF Score. Dense Score представляет исходную оценку сходства Qdrant. В блоке «Метаданные работы» доступны Vision Summary, Objects, Themes, Styles, Colors, Mood, Tags RU / EN и источник анализа, если журнал обработки позволяет связать его с сохранённой ревизией.

Блок «Как выполнен поиск» показывает исходный и рабочий запросы, решение обработчика диалога, фильтры, количество кандидатов, факты RAG, выбор composer и время этапов. Laravel записывает данные из того же поискового вызова. FastAPI возвращает время embedding, запроса к Qdrant и проверки доступности, число кандидатов Qdrant и фактические фильтры. Dense Rank следует порядку после проверки публичности в FastAPI, а RRF Rank отражает ранжирование до финальной сортировки и фильтрации Laravel. Если стадия пропущена или показатель отсутствует, в JSON используется `null`. Число `0` означает, что этап действительно выполнился и вернул пустой набор.

Для доступных кандидатов сохраняются ранги, оценки и причины исключения, например выход за страницу Hybrid, отсутствие факта в бюджете или отсутствие выбора composer. Метаданные сохраняются для приоритетных 20 работ. Снимок ограничен 100 кандидатами и 64 КиБ до шифрования. Остальные работы могут присутствовать в выгрузке с рангами и `metadata: null`. Текст атрибуции в исследовательских фактах скрывается. Настройки и сведения о моделях фиксируются при запросе. Токены, системные промпты, векторы и изображения в снимок не записываются.

Диагностика хода шифруется и сохраняется вместе с ходом. Переоткрытие истории и экспорт проверяют актуальные права на публикации, включая исключённых кандидатов и их факты. Счётчики этапов по-прежнему описывают момент выполнения запроса. Прямые вызовы `/assistant/search` и `/assistant/answer` поддерживают диагностику в ответе, а хранение использует маршрут сохранённого диалога.

## Включение в локальном контуре

В `docker/.env` для целевого локального Compose-проекта добавьте разрешённые ID аккаунтов через запятую. Значения `7,14` приведены для примера.

```ini
APP_ENV=local
AI_ASSISTANT_DEBUG_ENABLED=true
AI_ASSISTANT_DEBUG_USER_IDS=7,14
```

Пересоберите контейнеры с новым кодом и миграцией по штатной команде `./scripts/docker.ps1 up`. Затем войдите под разрешённым аккаунтом, откройте `/assistant` и включите «Диагностика поиска». Для сохранения новых снимков требуется диалог с включёнными историей и RAG. При выключенном флаге доступен обычный экспорт своего диалога, если включена история. Проверка среды, флага, списка ID и принадлежности диалога выполняется в Laravel.

Для прямых запросов к истории и записи ходов режим запрашивается заголовком `X-Assistant-Debug: 1`. Кнопка «Экспорт JSON» выбирает обычный экспорт при выключенном переключателе и добавляет `?debug=1` при включённом.

## Формат экспорта

Файл `library-stroll-chat-{date}-{id}.json` записывается в UTF-8 с отступами. Дата в имени следует часовому поясу приложения. `exported_at` содержит время с часовым поясом в ISO 8601. Экспорт проходит по всем ходам хронологически независимо от страницы истории.

| Поле | Содержимое |
|---|---|
| `export_schema_version`, `exported_at`, `conversation` | Версия формата `1`, время экспорта и данные выбранного диалога |
| `messages` | Запрос и ответ по каждому ходу, связанные общим `turn_id` и порядковым номером |
| `sources` | Итоговые карточки по `turn_id`, включая ID, заголовок и публичную ссылку |
| `metadata` | Снимки метаданных по `turn_id` и `artwork_id` |
| `diagnostics` | Запросы, путь обработки, фильтры, счётчики, ранги и доступные исключённые кандидаты |
| `rag` | Подготовленные для composer факты, признак попытки HTTP-вызова, действие и подтверждённые ссылки плана |
| `performance`, `configuration`, `errors` | Замеры времени, модели и флаги, ошибки, fallback и причины исключения по ID работы |

Обычный файл включает первые три строки таблицы. В расширенном файле диагностические разделы старых ходов содержат `null`. Для новых ответов с карточками без цитат сохраняются ID результатов. Для старых fallback-ходов, у которых такие карточки ранее не сохранялись, экспорт содержит запрос и статус. Ответы с цитатами восстанавливаются по сохранённым проверяемым ссылкам на факты. Если ревизия или факт изменились, устаревшие цитаты исключаются. При наличии снимка расширенный экспорт сохраняет исходный порядок карточек и порядок цитирования composer. Экспорт выполняет только чтение истории и проверку доступности работ.

## Контрольные запросы

Проверено 13 исходных формулировок в новых диалогах и те же 13 в одном последовательном диалоге. Использован проект `library-stroll-54-diagnostics`, копия MySQL, медиа и Qdrant с 511 работами. В диалогах действовали RAG и контекст. Нормализация и ColBERT были выключены. Dense использовал `qwen3-embedding:0.6b`, resolver и composer использовали `qwen3:8b`. Снимки метаданных относятся к `qwen3-vl:4b-instruct`, версия схемы и промпта индексации `1/1`.

Для визуальной оценки проверены итоговые карточки по миниатюрам. В столбце «Оценка» указано число полных, частичных, нерелевантных и неизвестных совпадений в этом порядке. ## Где появляются нерелевантные работы

Во всех 25 поисках лексический поиск по целой фразе в заголовке вернул 0 совпадений. Dense и Hybrid вернули по 50 работ в том же порядке. RAG получил факты по первым пяти работам. При упаковке приоритет получили названия, пользовательские описания и публичная атрибуция. Визуальные факты описания, объектов, тем или тегов уместились только в 2 из 25 поисков.

| Работа и запрос | Dense Score | Dense / Lexical / Hybrid | Что произошло после поиска |
|---|---:|---|---|
| #348 Abstract background wallpaper 3, «Что ты умеешь?» в новом диалоге | 0,240 | 3 / — / 3 | Composer выбрал заголовок. На картинке красные абстрактные линии. |
| #348 Abstract background wallpaper 3, «Видео.» в обоих режимах | 0,388 | 1 / — / 1 | Фильтр ограничил поиск изображениями. Composer выбрал заголовок статичного изображения. |
| #298 Twitter Bird Sketch, «Хочу попугая.» в обоих режимах | 0,288 | 1 / — / 1 | Composer выбрал заголовок. Vision правильно описал логотип птицы. Попугай #294 найден на позиции 4 и тоже показан. |
| #298 Twitter Bird Sketch, «Найди изображения птиц у воды.» | 0,479 | 10 / — / 10 | До RAG работа не дошла. |
| #298 Twitter Bird Sketch, «鳥を見つける» | 0,446 | 1 / — / 1 | Composer выбрал заголовок и описание. Логотип визуально передаёт образ птицы. |

Для «Мне нужен портрет с бородой.» #329 попал в Dense и Hybrid на позиции 2. Vision описывает женщину с кудрявыми светлыми волосами. Composer получил для этой работы публичные факты и включил её в ответ. Полностью подходящие #319 и #191 тоже показаны. Для «Инопланетяне.» composer выбрал изображения самолётов и ракеты на позициях 1–2. Эти случаи показывают, что подтверждение доступных фактов в текущем composer допускает карточки с частичным совпадением или без запрошенного визуального признака.

Контекстный resolver обработал «Что ты умеешь?» как уточнение в последовательном диалоге. Первый ход нового диалога пошёл прямо в поиск. Для «Видео.» resolver выбрал новый поиск в последовательном режиме, где действовал тот же фильтр `image`. Оценённые случаи не устанавливают универсальный порог Dense Score.

## Проверки и замеры

| Проверка | Результат |
|---|---|
| Laravel | 146 тестов ассистента, включая сохранение снимка, `null` для старых сообщений, экспорт 22 ходов при странице в 20, порядок карточек и удаление недоступных источников из карточек, кандидатов и RAG |
| FastAPI | 191 тест прошёл, 2 пропущены существующими условиями |
| Клиент | 24 теста JavaScript, сборка Vite, просмотр диагностических карточек и блока поиска после перезагрузки, скачивание контрольного JSON, десктоп и мобильная тёмная тема |
| Доступ | Обычный экспорт своего диалога `200`, расширенный экспорт без авторизации `403`, чужой диалог `404` |
| Количество обращений | Автотест проверил один вызов Dense и один вызов composer на ход. Чтение истории и экспорт новых AI-запросов не добавили. |
| Порядок | Три парных запроса с переключателем и без него дали тот же набор карточек в том же порядке. |
| Основной каталог | 511 актуальных Vision-записей и 511 точек, Cosine 1024. Канонический SHA-256 точек с payload и векторами совпал со снимком восстановления. Максимальная разница компонент равна 0. |

Медианное локальное время сбора снимка по трём парным замерам составило 19,46 мс, диапазон 17,71–20,46 мс. Изменение полного времени HTTP лежало в диапазоне от −469 до +249 мс. Такой разброс и размер серии не позволяют отделить стоимость записи снимка от колебаний inference по полному времени ответа.

В 26 контрольных ходах медиана HTTP составила 2,23 с для нового диалога и 2,63 с для последовательного. Медиана Dense составила около 75 мс в обоих режимах, медиана composer составила 1,94 и 1,97 с соответственно. Таймаутов в контрольном прогоне не было. Обработка таймаута и запись fallback проверены отдельным тестом с HTTP 504.

Артефакты находятся в `storage/app/ai-stage-05-04/5.4-1a0/`. `controls.json` содержит все ходы, `control-summary.json` содержит ранги и сводку, `visual-review.json` связывает ручную оценку с ID ходов и карточек. `assistant-diagnostics-desktop.png`, `assistant-trace-desktop.png` и `assistant-diagnostics-mobile.png` показывают интерфейс. Полный последовательный диалог выгружен в `library-stroll-chat-*.json`. В `overhead-pairs.json`, `active-metadata-integrity.json` и `index-integrity.json` сохранены измерения и сверка.

## Следующий этап

1. Разделить намерения «поиск изображения», «поиск видео» и «справка об ассистенте» и измерить выбор обработчика на новых и последовательных диалогах.
2. По визуально размеченным контрольным запросам измерить, как состав фактов RAG влияет на потерю признаков «попугай», «борода», «синий» и «у воды». Отдельно сравнить явное упоминание признака с его отсутствием в запросе к composer.
3. Подготовить более широкую разметку для сравнения LLM-маршрутизации и кандидатов Dense. Включить неоднозначные имена, японские запросы и примеры с низкими сходствами.
